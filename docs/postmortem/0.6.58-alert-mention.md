## 1. 타임라인 및 결과 요약

- **배치**: 새 워크스페이스에서 z-opus 라벨링, z-sol을 `herdr agent start … --kind codex -- -m gpt-6.2-sol -c model_reasoning_effort=high -c service_tier=fast`로 열었다. 상태줄 `GPT-6.2-Sol high fast`를 확인했다.
- **구현(z-opus)**: 호출 대상 판정 `shouldMention`(domain `alert-message.mjs`), 설정 `ZZIK_ALERT_MENTION_USER_ID`(domain `alert-config.mjs`, 17~20자리 숫자만), 전송(infra `discord-alerts.mjs`, 본문 앞 `<@ID>`, `allowed_mentions:{parse:[],users:[ID]}`). 테스트를 먼저 써서 실패를 확인한 뒤 구현했다. 실제 ID는 release `.env`에만 넣었다.
- **실발송 확인**: 합성 이벤트 3건(주의→위험, 주의→정상, 주기 리셋, 라벨 `[테스트]`)을 실제 알림 웹훅으로 보냈고 사용자가 수신·호출을 확인했다.
- **게이트 정리(z-sol)**: 전체 테스트에서 `tests/worker/metrics.workerd.test.ts`·`trend.workerd.test.ts` 3건이 변경 전 dev에서도 실패했다. 픽스처 날짜를 크론 시각에서 계산하도록 고쳤다(`d9336f8`).
- **배포**: `ship.mjs --apply`로 릴리스·수집기 반영·완료 알림까지 진행했다.

## 2. 잘된 점

- **공개 저장소에 개인 식별자 미노출**: 저장소가 PUBLIC임을 먼저 확인하고 ID를 환경변수로 분리했다. 사용자가 작업 중 "하드코딩하지 말라"고 보냈을 때 이미 그렇게 되어 있었다. ID는 로그·dry-run 미리보기에도 남지 않음을 테스트로 고정했다.
- **호출 범위를 좁게 유지**: 기존 "멘션 차단" 원칙을 깨지 않고 `allowed_mentions.users`를 그 한 명으로 제한해 `@everyone`·역할 호출이 섞일 여지를 없앴다.
- **env 추가를 배포 전에 안전하게 선반영**: 현재 코드가 읽지 않는 키라 먼저 넣어도 동작이 바뀌지 않는다. 지난 회고(0.6 patch train)의 줄바꿈 누락 사고를 반영해 파일 끝 줄바꿈을 먼저 확인했다.
- **기존 실패를 내 변경과 분리**: 변경을 잠시 치우고 dev에서 같은 3건 실패를 재현해 무관함을 확인한 뒤 z-sol에 별도 조각으로 넘겼다.

## 3. 문제와 근본 원인

### P1. 날짜 고정 픽스처가 시간이 지나 저절로 실패

- **사실**: metrics 테스트는 크론 시각을 2026-11-17로 고정했고, `/pub/trend`는 workerd 실제 시각으로 48시간 신선도를 평가해 11-21에 `stale`이 됐다. trend 테스트는 OpenRouter 등록일을 11-13으로 고정해 "최근 7일" 범위를 벗어났다.
- **근본 원인**: 실제 시계를 쓰는 통합 테스트에 고정 날짜 문자열을 넣었다. 작성 당일에는 통과해 리뷰에서 드러나지 않는다.
- **조치**: 픽스처 날짜를 실행 시각에서 계산하도록 수정. `layered-tdd` 스킬에 "실제 시계 통합 테스트의 픽스처 날짜는 기준 시각에서 계산" 규칙을 추가했다.

### P2. 라벨 스크립트가 워크스페이스 접두어를 붙이지 않음

- **사실**: `SELF_LABEL=opus`로 실행하니 `opus`로 붙어 `z-opus`로 수동 rename했다.
- **근본 원인**: 접두어 규칙은 문서(`docs/harness/agents.md`)에만 있고 스크립트에는 없었다.
- **조치**: `scripts/herdr-label-models.sh`에 `LABEL_PREFIX`(한 번만 붙임, 이미 붙은 이름 유지)를 추가하고 테스트를 넣었다. 문서·스킬 사용 예를 `LABEL_PREFIX=z- SELF_LABEL=opus`로 바꿨다.

### P3. Codex 전역 effort가 구성표와 다름

- **사실**: `~/.codex/config.toml`의 effort가 `low`라 구성표의 high와 달랐다. 실행 인자 `-c model_reasoning_effort=high`로 맞췄다.
- **근본 원인**: Codex 실행 방법이 문서에 없어 전역 기본값에 기대게 된다.
- **조치**: `docs/harness/agents.md`에 Codex 실행 명령과 상태줄 확인을 적었다. 홈 설정 파일은 건드리지 않는다.
