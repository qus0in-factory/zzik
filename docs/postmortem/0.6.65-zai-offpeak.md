# 부검·회고: Z.AI off-peak 감지·알림과 사용량 링크 (0.6.64~0.6.65)

- **일자**: 2026-11-21
- **대상**: v0.6.64(Z.AI off-peak 배지·Discord 알림), v0.6.65(Z.AI 사용량 링크 변경). 사용자 요청 "zai peak/offpeak 감지 기능, 디스코드 알림도 기존처럼"과 "zai는 Coding Plan 사용량 링크로"
- **워커 구성**: z-opus(총괄·병합·릴리스), z-sol(Codex `GPT-6.2-Sol`, high, Fast: 일정·테스트), z-neon(Antigravity `Gemini 4 Neon`, high: 공식 근거 조사), z-glm(OpenCode `GLM-5.3` Z.AI Coding Plan, high: 문서)
- **결과**: 공유 일정에 Z.AI(평일 peak 06:00–10:00 UTC = 15:00–19:00 KST, 그 외·주말 GLM 크레딧 50%)를 추가해 배지와 기존 Discord 알림이 그대로 동작한다. 두 릴리스 모두 ship 전 단계 PASS, 사용자 운영 확인 완료.

## 1. 타임라인

- 워커 패널을 처음엔 같은 탭에 split으로 열었다가, 사용자 지시("같은 패널 말고")로 닫고 워커마다 별도 탭으로 다시 열었다.
- 첫 지시는 z-sol 한 명에게 조사·구현·문서를 모두 맡겼다. 사용자 지시("neon, glm에게 나눠서")로 z-neon(공식 조사)·z-glm(문서, 별도 워크트리)에 다시 나누고 z-sol에는 "문서 빼라"는 추가 지시를 보냈다.
- z-sol은 이미 공식 근거를 달아 문서까지 커밋한 뒤였고, 추가 지시는 입력창에만 남았다. z-glm의 문서 브랜치는 내용이 겹쳐 버렸다.
- z-neon 조사값과 z-sol 구현값이 일치(docs.z.ai, 확인 2026-11-21). dev 병합 → ship `--apply`로 0.6.64 배포(Worker·수집기 반영).
- 사용량 링크 교체는 z-opus가 직접(1줄 + 테스트) 처리해 0.6.65 배포, `--kind verify`로 화면 확인 요청.

## 2. 잘된 점

- 기존 off-peak 구조(공유 일정 데이터 → 배지·알림)가 확장점이 되어, 새 제공자를 데이터와 테스트만으로 추가했다.
- 제3자 자료가 엇갈렸지만 공식 문서를 두 워커가 독립 확인해 값이 일치했다.

## 3. 문제와 근본 원인

### P1. 작업 분할을 지시 후에 바꿔 중복 작업 발생
- **사실**: z-sol 진행 중에 범위 축소를 덧붙였고, 이미 끝난 문서를 z-glm이 다시 썼다.
- **근본 원인**: 첫 지시 때 일을 조사·구현·문서로 쪼개지 않았다. 진행 중 워커에 덧붙이기 금지 규칙을 어겼다.
- **조치**: 지시 전에 조각으로 나눠 동시에 보낸다. 범위를 바꿔야 하면 워커 완료 보고를 먼저 확인하고 겹치는 쪽을 취소한다.

### P2. 워커가 메인 체크아웃에서 브랜치를 바꿈
- **사실**: z-sol에 워크트리 경로 없이 브랜치만 지정해, 메인 저장소 체크아웃이 `0.6/zai-offpeak`로 바뀌었다. 첫 dev 병합이 "Already up to date"로 헛돌았다.
- **조치**: 코드 작업 워커에는 항상 `.worktree/<트랙>` 경로를 준다(`herdr-orchestration` 워크트리 절).

### P3. 워커 패널을 split으로 엶
- **조치**: 워커는 `herdr tab create --label <이름>`으로 탭마다 하나씩 연다(`docs/harness/agents.md`).

## 4. 남은 사항
- Z.AI 공휴일 예외, off-peak 동시성 상향 수치, MCP 호출 50% 적용 여부는 공식 문서에 없어 미확인.
- 배지는 계정 플랜 유형을 조회하지 않는다. Legacy V2 플랜은 배수 방식이라 50% 표기와 다르다.
