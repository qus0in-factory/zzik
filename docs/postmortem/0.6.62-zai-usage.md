- **일자**: 2026-11-21
- **대상**: v0.6.60~0.6.62. 사용자 요청 "Z.AI Coding Plan 사용량 보는 것 만들어 줘"
- **워커 구성**: z-opus(총괄·통합·장애 수정), z-sol(Codex `GPT-6.1-Sol`, low, Fast: 수집기·스크립트), z-fable(Claude Code `Fable 5.2`, high: 웹·공용 계약), z-glm(OpenCode `GLM-5.3` Z.AI Coding Plan: 문서), z-hf(OpenCode `Hy4 flash Free`: fixture)

- **실측 해석**: 실제 응답 파일(0600, 확인 후 삭제)을 `buildZaiUsageView`에 넣어 두 창이 issues 없이 해석됨을 확인했다.
- **0.6.60 ship**: Worker 배포(17:11) 후 `usage_live_shape`가 `zai` 스냅샷 없음으로 FAIL → ship이 `deploy_worker`에서 멈춤. 수동 `collector-apply --apply`에서 PM2 재시작 → 수집기가 `ledger_start_failed`로 재시작 반복.

## 2. 잘된 점

- **실측 형태 먼저, fixture 공유**: 엔드포인트를 한 번만 호출해 값 없이 형태만 보고, 합성 fixture를 기반 커밋으로 넣어 세 트랙이 같은 가정으로 병렬 작업했다. 충돌 없이 병합됐다.
- **복구 전 복사본 검증**: 수정한 원장 코드를 운영 원장 복사본으로 먼저 열어 보고(순번 1272 유지) 배포했다. 원장 삭제·재초기화 없이 forward-fix했다.
- **비밀값 비노출**: 키·응답 값은 출력하지 않았고 임시 파일은 0600으로 만들고 지웠다.

## 3. 문제와 근본 원인

### P1. 새 제공자 추가로 기존 원장 기동 거부 → 수집 전면 중단 (심각)

- **사실**: `openSqliteLedger`는 기존 원장의 `provider_state` 행 수가 `PROVIDERS.length`와 같아야 열렸다. 제공자가 6→7이 되자 `empty_ledger`로 거부, PM2가 재시작을 반복했다.
- **근본 원인**: 원장은 최초 생성 때만 제공자 행을 만들고 이후 추가 경로가 없었다(ollama 등은 원장 도입 전에 추가돼 드러나지 않았다). 테스트는 매번 새 원장을 만들어 "이전 목록으로 만든 원장" 경우가 없었다. 재시작 전에 새 코드가 운영 원장을 열 수 있는지 확인하는 단계도 없었다.
- **조치**: 누락 제공자 행만 추가(빈 원장·모르는 제공자 행은 계속 거부) + 테스트. `scripts/ledger-preflight.mjs`(운영 원장 복사본을 release 코드로 열기)를 추가하고 `collector-apply`가 PM2 재시작 전에 실행해 실패하면 재시작하지 않게 했다(`stage: ledger_preflight`).

### P2. 배포 검증이 수집기 반영 전에 새 제공자 데이터를 요구

- **사실**: ship 순서는 Worker 배포 → 검증 → 수집기 반영인데, z-sol이 검증 목록에 `zai`를 넣어 아직 없는 스냅샷을 FAIL로 판정했다.
- **근본 원인**: 단계 순서와 검증 범위를 함께 보지 않았다.
- **조치**: 스냅샷이 아직 없는 제공자는 `SKIP(no_snapshot)`. 형태가 틀린 기존 데이터는 여전히 FAIL.

### P3. 자격 형식 가정 누락 (`access` vs `key`)

- **사실**: 지시문에 `{type:"key", key}`를 적었지만 기존 리더는 OAuth `access`만 읽어 `no_credentials`가 됐다. 단위 테스트는 가짜 DB에 `access` 형태만 넣었다.
- **근본 원인**: 실측 자격 형식을 합성 테스트 입력으로 고정하지 않았다. 리뷰(z-opus)도 클라이언트·배선만 보고 리더 재사용 가정을 확인하지 않았다.
- **조치**: `type:"key"` 행 테스트 추가 후 수정. 새 제공자 체크리스트에 "실측 자격 형식을 합성 테스트로 고정"을 넣었다.

### P4. 워크트리 `pnpm install` DNS 실패

- **사실**: z-sol 워크트리에서 레지스트리 DNS 오류로 설치 실패, 상위 `node_modules`로 대신 실행해 Wrangler 의존 테스트를 못 돌렸다. 병합 후 총괄이 전체 테스트로 보완했다.
