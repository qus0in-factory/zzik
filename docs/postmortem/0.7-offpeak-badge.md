# 부검·회고: OpenCode·Ollama off-peak 배지 (0.6.17)

- **일자**: 2026-11-15
- **대상**: v0.6.17 (PR #89, main `9fdd833`). 설계 `/tmp/offpeak-design.md`, ADR `docs/adr/0.7-offpeak-badge.md`, 조사 `docs/research/0.7-offpeak-schedules.md`
- **워커 구성**: sol(Codex), hydro(agy), grok(Grok Build), ds, fable(설계·핵심 리뷰), opus(총괄)
- **결과**: 테스트 1,686건에서 1,744건. 배포 게이트 PASS. 운영 화면은 사용자가 확인하고 OK.

## 1. 타임라인 및 결과 요약

- **조사 분배**: opus가 WebSearch로 조사를 시작하자 사용자가 거부했다. 이후 sol이 OpenCode Go, hydro가 Ollama, grok이 DeepSeek 공식 API를 조사하고 fable이 설계를 병렬로 잡았다. 설계는 스케줄을 주입하는 구조라 조사 값 없이도 구현 골격이 갈렸다.
- **실응답 형상**: ds가 `scripts/usage-live-shape.sh`로 OpenCode·Ollama 최신 ok 원문을 읽었다. off-peak·할인 신호 필드가 없어 배지는 응답이 아니라 스케줄 × 시계로 정했다(ADR D8).
- **구현**: core는 sol(`0.7/offpeak-core`), ui는 hydro(`0.7/offpeak-ui`). 계약 타입을 두고 worktree를 나눠 rebase 충돌을 줄였다.
- **검수**: fable이 분 단위 오라클 80,640건을 대조했다. 교차 리뷰는 fable·grok·ds, 이어서 work-reviewer. 여기서 잡힌 것은 Ollama 할인 누락·비활성 할인 문구·`days: []`·평일 경계 표·라이트 대비·배선 테스트다. 수정은 `d78d982`, `bf65ce1`, ui `d484acc`·`9be120d`. 요일 표기는 이 리뷰와 테스트를 통과한 뒤 화면 확인에서 발견해 `f8a74f5`로 고쳤다.
- **문서**: ADR이 "구현 전"과 effect 누락인 채로 남아 work-reviewer가 FIX-doc. 구현 문구·`effect`·현지 날짜 요일 규칙으로 고쳤다.
- **배포**: 0.6.17. 로컬 `/api/usage`는 Access JWT와 원격 DB가 필요해 `?fixture=normal`로 스크린샷을 찍었다. 운영 확인은 사용자가 했고, 확인 요청은 Discord로 보냈다.

## 2. 잘된 점

- **조사와 설계의 분리**: 제공자별 조사를 워커 세 갈래로 나누고, fable 설계는 빈 스케줄로도 조립이 끝나는 주입형으로 두어 값 확정 전에 레이어를 고정했다.
- **worktree와 계약**: core와 ui를 다른 worktree에 두고 타입으로 맞춰 병합 충돌을 줄였다.
- **응답에 신호가 없다는 실측**: ds 형상 조사가 "응답을 정본으로 읽지 않는다"를 추측이 아닌 키 집합으로 남겼다.
- **독립 오라클과 삼중 리뷰**: fable 전수 대조와 fable·grok·ds 리뷰, work-reviewer가 할인 범위·디코더·경계 표·ADR 불일치를 구현 통과 후에 잡았다. 요일 표기는 이 리뷰 성과에 넣지 않는다. 테스트와 워커 리뷰가 통과한 뒤 opus의 fixture 화면 확인에서 발견해 `f8a74f5`로 고쳤다.
- **스크린샷이 테스트를 넘김**: 일 19:55 KST에 요일이 빠진 배지를 opus가 fixture 화면에서 봤다. 단위 테스트와 워커 리뷰는 그 시각을 통과한 상태였다.

## 3. 문제와 근본 원인

### P1. 총괄이 조사·워커 배분을 사용자 역할 밖에서 정함

- **사실**: (1) opus가 직접 웹 조사를 시작했다. (2) sol 주간 한도 22%를 이유로 호출을 아낀다고 했다. (3) 워커 4명을 watcher 하나에 묶었다. (4) 탭5에 grok이 있는데 탭6에 다시 띄웠다. (5) 운영 화면 확인을 에이전트가 하려 했다.
- **근본 원인**: 조사·대기·추가 실행을 총괄이 편의로 줄였다. 한도 판단과 운영 확인의 주체가 사용자인데 그 경계를 총괄이 넘었다. 추가 전에 pane 목록을 보지 않았다.
- **조치**: 조사도 워커가 한다. 한도 때문에 역할을 빼는 판단은 사용자 몫이다. watcher는 워커 1명당 1개다. 에이전트를 띄우기 전에 pane 목록을 본다. 운영 확인은 사용자가 하고, 요청은 Discord로 보낸다. `herdr-orchestration`에 이 네 가지를 적는다.

### P2. 프롬프트 조립과 CLI 입력으로 지시가 잘리거나 잘못 들어감

- **사실**: `printf "$D"`로 프롬프트를 만들자 본문의 `50%)`가 printf 지시자로 먹혀 TDD·커밋·결과 파일 안내가 잘렸다. 재전송했다. Codex·agy의 effort 변경은 슬래시 팝업 때문에 Tab→Enter(Codex는 Enter 2회 또는 Reasoning 메뉴)가 필요하고, Escape가 입력을 지우지 않아 `//model`이 프롬프트로 나갔다. `herdr pane read <에이전트이름>`은 `pane_not_found`다.
- **근본 원인**: 워커 본문을 포맷 문자열로 다뤘다. 모델별 슬래시 메뉴 동작을 한 입력 절차로 가정했다. pane 이름과 pane ID·`herdr agent read`를 구분하지 않았다.
- **조치**: 프롬프트 조립에 printf를 쓰지 않고, 변수를 그대로 붙이거나 quoted heredoc을 쓴다. effort 변경은 모델별 키 절차를 `herdr-orchestration`에 적는다. 출력 읽기는 pane ID 또는 `herdr agent read <이름>`이다.

### P3. 검수 에이전트가 메인 worktree를 detach 함

- **사실**: work-reviewer가 검수 중 메인 worktree에서 `git checkout --detach dev`를 실행했다. 즉시 복구했다.
- **근본 원인**: 읽기 검수와 체크아웃을 구분하지 않았다. 메인 worktree는 사용자의 현재 브랜치다.
- **조치**: 검수 에이전트는 메인 worktree에서 checkout·switch를 하지 않는다. 읽기는 대상 worktree 경로, `git show`, `git merge-tree`로 한다. 반영 위치는 `.claude/agents/work-reviewer.md:11`, `.claude/agents/worker-watcher.md:12`(`03a4842`)와 `herdr-orchestration`이다.

### P4. 요일 없는 배지 — 테스트는 통과, 화면에서 발견

- **사실**: 요일 조건이 "전환까지 24시간 이상"이었다. 일 19:55 KST(전환까지 24시간 미만, 현지 날짜는 내일)에 OpenCode 배지가 `10:00까지`만 보였다. 테스트와 워커 리뷰는 통과했다. opus가 fixture 스크린샷에서 봤다. 수정 `f8a74f5`. 첫 스크린샷은 `?fixture=normal` 없이 찍어 전 섹션이 오류였다.
- **근본 원인**: 테스트가 UTC로 24시간 경계를 재고, 현지 자정과 UTC 자정이 어긋나는 시각을 넣지 않았다. 로컬 API는 Access 뒤에서 실데이터를 주지 않는데 fixture 없이 촬영했다.
- **조치**: 요일은 현지 연·월·일이 다를 때 붙인다(`f8a74f5`). 배지 스크린샷은 `?fixture=normal`로 찍고, 현지 자정 직전·정각과 UTC 날짜만 다른 당일 전환을 테스트에 둔다. 로컬 스크린샷은 워커가 촬영·검수해 보고하고, opus가 직접 열어 최종 판정한다. 테스트와 워커 검수는 이 판정을 대체하지 않는다(사건 11). 운영 화면은 Discord 확인 요청 후 사용자가 확인한다.

### P5. 할인 문구가 제공자 분기와 비활성 문장에 묶임

- **사실**: 할인 문장이 OpenCode에만 있었다. opus가 조사 문서와 대조해 Ollama 누락을 봤고 `d78d982`로 더했다. fable은 비활성 description이 지금 할인 중인 것처럼 읽힌다고 했고(F1), 제공자 분기가 다음 제공자에서 반복된다고 했다(F2). `bf65ce1`에서 `effect: { target, discountPercent }`로 옮기고, 비활성은 `off-peak 동안 …`으로 바꿨다. `days: []`는 디코더가 통과시키던 것을 `invalid_window`로 거절했다(F3). 평일 경계 표 테스트가 없어 `10:00`을 바꿔도 통과하던 구멍을 월요 01·04·06·10시와 12·18시 표로 막았다(F4).
- **근본 원인**: 혜택을 스케줄 데이터가 아니라 app의 제공자 이름으로 적었다. 초기 문구 테스트(`0a2b16f`)에는 활성·비활성 시각이 있었다. 그 기대값이 OpenCode 활성과 Ollama 할인 없음, OpenCode 비활성 description의 무조건 할인 문구를 정답으로 고정했다. 테스트가 없었던 것이 아니라 잘못된 기대값이 문제였다. 실데이터 시각을 단언하지 않는다는 설계 문장을, 값이 확정된 뒤에도 유지했다.
- **조치**: 혜택은 `effect`만 본다. 비활성 할인은 조건형 키를 쓴다. 운영 스케줄 테스트는 조사 문서의 평일 경계를 시작 포함·끝 미포함으로 고정한다.

### P6. ui 대비·배선 테스트가 화면 경로와 달랐음

- **사실**: ds 리뷰에서 라이트 배지 대비가 3.82:1(AA 미달)이었다. `d484acc`에서 `--usage-ok-text`를 두고 배지 색을 바꿔 6.67:1이 됐고, 프롭 주입 배선 테스트를 `UsageDeps.offpeak` 실경로로 바꿨다. `9be120d`에서 실데이터 스케줄을 인라인 가짜 스케줄로 분리하고, 대비 회귀·생략 사례를 보강했으며 UsageSection의 임시 offpeak 프롭을 제거했다.
- **근본 원인**: 배지 색을 사용량 정상색으로 쓰면서 대비를 측정하지 않았다. 테스트가 `OffpeakBadge`에 문구를 직접 넣어 `useOffpeakNotice`와 `UsageDeps.offpeak`를 건너뛰었다.
- **조치**: 배지 전경은 대비가 확인된 토큰을 쓴다. 배선 테스트는 deps로 스케줄을 넣고, 기대 시각은 그 테스트 안의 가짜 구간으로 고정한다.

### P7. ADR이 구현과 어긋난 채 남음

- **사실**: 구현 뒤에 ADR 상태가 "구현 전"이었고 `effect`와 실제 `offpeak.*` 문구, 현지 날짜 요일 규칙이 없었다. work-reviewer가 FIX-doc으로 돌려보냈다.
- **근본 원인**: ADR을 구현 전에 커밋한 뒤, 리뷰에서 바뀐 계약을 문서 브랜치에 되돌리는 단계가 배포 검수 앞에 없었다.
- **조치**: 구현 확정 커밋과 문구 키가 정해지면 ADR 상태·키·`effect`·표기 규칙을 그 커밋에 맞춘 뒤 검수한다. 검수는 ADR 문장과 `shared/messages/ko.ts`를 대조한다.

## 5. 후속

- OpenCode Go·Ollama의 중국 공휴일 적용은 미확인이라 스케줄에 없다. 제공자 문서가 공휴일을 적으면 그때 예외를 넣는다.
- OpenCode Zen의 off-peak는 미확인이다. 대시보드 OpenCode는 Go 사용량 시간대만 쓴다.
- 상류 응답에 off-peak 필드가 생기면 스케줄보다 응답을 정본으로 재검토한다(ADR D8).
- DeepSeek 직접 API의 피크 창은 OpenCode Go와 같고 공휴일 제외가 더 있다. zzik 제공자가 아니므로 배지를 두지 않는다.
- 위 표의 스킬 문장(printf, watcher 비율, 검수 checkout 금지)은 이 회고 커밋이 스킬 파일을 고치지 않는다. 반영은 별도 커밋 `03a4842`에 있다.
