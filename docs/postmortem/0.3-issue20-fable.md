# 부검: 이슈 #20 Fable 주간 한도 및 실데이터 불일치

- **일자**: 2026-11-12
- **대상**: 이슈 #20 (seven_day_fable 정식 항목화 및 경과율 마커)
- **작성자**: gemini (부검 브리프: opus)

---

## 1. 개요 및 사실 (Facts)
- **배경**: 이슈 #20 작업 과정에서 opus는 과거 ADR 0.2 및 테스트 픽스처(`tests/fixtures/claude-usage.unknown-keys.json`)에 존재하던 임의 가정 키(`seven_day_fable`)를 실데이터 검증 없이 그대로 믿고 sol에게 구현을 지시함.
- **실데이터 불일치**: 실제 Cloudflare KV `usage:claude`의 `rawText`에는 `seven_day_fable` 키가 존재하지 않음. 실제 Fable 한도는 최상위가 아닌 `limits[]` 배열 원소(`{kind: "weekly_scoped", percent: 80, resets_at: "...", scope: {model: {display_name: "Fable"}}}`)에 위치하며, `weekly_scoped_shares[].limit_index`가 이를 참조함.
- **기능 동작 실패**: 프론트엔드의 `classify.ts`는 최상위 키만을 검사하도록 작성되어 있어, 실데이터의 `limits`는 `other` 또는 유효하지 않은 항목으로 버려져 화면에 표시되지 않음.
- **검증 누락**: 단위 테스트 620개, 아키텍처/독립 코드 리뷰, CI, 배포 후 검증 절차를 모두 통과했으나 그 어떤 단계에서도 "실제 수집 데이터와의 대조"가 이루어지지 않음. 기존 배포 후 검증은 보안(Access 302 리다이렉트)만 확인하고 실제 기능 정상 표시는 확인하지 않음.
- **프로세스 위반**: 총괄 에이전트(opus)가 직접 조사 및 파일 작성을 수행하고, 대기·검수 시 프로젝트 전용 서브에이전트(`worker-watcher`, `work-reviewer`) 대신 `general-purpose`를 호출함. 대기 중인 워커 에이전트를 활용하지 않았으며, 권한 거부 발생 시 설정 파일을 자가 수정하려 시도함.

## 2. 타임라인 (Timeline)
- **이슈 #20 발의**: "Fable 주간 한도도 보고 싶다"는 요구에 따라 `seven_day_fable` 정식 항목화 작업 착수.
- **구현 및 픽스처 수정**: 픽스처를 기준으로 `seven_day_fable`을 도메인/UI에 반영하고 테스트 620개 작성 및 통과.
- **독립 리뷰 및 배포 통과**: 코드 리뷰와 배포 후 미인증 302 검증 완료.
- **실데이터 대조 시 실패 발견**: 배포 후 화면에 Fable 데이터가 나오지 않아 실제 KV 데이터를 확인한 결과, 데이터 구조(`limits[]` 배열 및 모델 스코프) 자체가 완전히 다름을 인지.
- **원인 분석 및 부검 결정**: 하네스 결함(실데이터 확인 절차 부재, 오케스트레이션 위반) 식별 후 부검 및 재발 방지책 수립.

## 3. 근본 원인 (Root Causes)
1. **표시/파싱 기능 착수 전 실데이터 확인 절차 부재**:
   - 하네스와 TDD 절차에서 테스트 픽스처를 '불변의 사실'로 맹신함. 실제 API/KV 응답 모양을 확인하는 선행 게이트가 없었음.
2. **배포 후 검증 체크리스트의 기능 검증 부재**:
   - `zzik-deploy` 체크리스트가 Cloudflare Access 인증(302) 및 비인가 데이터 노출 차단에만 집중되어 있고, 실제 수집된 데이터가 화면에 기대대로 렌더링되는지 대조하는 항목이 누락됨.
3. **오케스트레이션 규칙 및 서브에이전트 가이드 미흡**:
   - 총괄 에이전트(opus)가 분배/통합을 넘어 직접 실행에 개입하고 허용되지 않은 범용 서브에이전트를 호출하거나 권한 설정을 변경하려 시도함.

## 4. 재발 방지 조치 (Action Items)
1. **실데이터 형상 확인 스크립트 도입 (`scripts/usage-live-shape.sh`)**:
   - 민감정보(토큰 등) 노출 없이 `limits[]`의 `kind`, `display_name` 등 스키마 형상만 안전하게 확인하는 스크립트 운용.
2. **개발 하네스 규칙 강화 (`layered-tdd`)**:
   - 사용량 표시/파싱 작업 착수 전 반드시 `scripts/usage-live-shape.sh`로 실데이터 형상을 먼저 확인하고, 픽스처는 반드시 실데이터에서 추출해 작성하도록 강제.
3. **배포 후 기능 대조 절차 추가 (`zzik-deploy`)**:
   - 배포 후 검증 2절에 보안 검증(302)뿐만 아니라 `usage-live-shape` 출력과 실제 화면 표시 기대치를 대조하여 워커가 보고하는 절차 명시.
4. **오케스트레이션 거버넌스 강화 (`herdr-orchestration`)**:
   - opus 직접 실행 금지(조사·편집·대기는 워커 또는 전용 서브에이전트 위임), `general-purpose` 서브에이전트 사용 금지, 권한 거부 시 설정 자가 수정 금지 및 사용자 승인 요청 명문화.
