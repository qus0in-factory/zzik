# 부검·회고: favicon·iOS 홈 화면 아이콘 (0.6.14~0.6.16)

- **일자**: 2026-11-15
- **대상**: v0.6.14 ~ v0.6.16 (PR #83·#84·#86), 이슈 #82(favicon 세트), #85(iOS 홈 화면 아이콘), 후속 #87
- **워커 구성**: sol(Codex), grok(Grok Build 4.7), hydro(agy Gemini 4 Hydrogen high), opus(총괄)

---

## 1. 타임라인 및 결과 요약
- **v0.6.14 (PR #83, sol 구현, 배포 `3d1845a2`)**:
  - RealFaviconGenerator 최신 수준으로 `favicon.ico`(16·32·48px), `favicon.svg`, `favicon-96x96.png`, `apple-touch-icon.png`(180px), `web-app-manifest-192x192.png`·`512x512.png`, `site.webmanifest`, `theme-color`(라이트/다크), `manifest` `crossorigin="use-credentials"`를 구성.
  - 기존 PNG에서 저빌 로고를 벡터(`public/favicon.svg`)로 재구성하고 로컬 Chrome/CDP 기반 `scripts/generate-favicons.mjs`를 도입.
- **hydro 1차 교차 리뷰 (`FIX` 3건)**:
  1. `site.webmanifest`의 `"purpose": "any maskable"` 결합 표기(88% 축소한 maskable 이미지를 `any` 겸용으로 쓰는 문제).
  2. `apple-touch-icon.png` 불투명 검사 공백(`maskable`만 검사).
  3. `favicon.svg` 눈 색 `#fff`(원본 크림색과 차이) 및 `#head` path 문자열 중복.
- **v0.6.15 (PR #84, grok 구현, 배포 `589f4be1`, hydro 2차 `PASS`)**:
  - `opus`가 처음에 "`any`에 같은 파일을 재사용할 수 있다"고 잘못 지시해 `grok`이 그대로 구현했으나, `hydro` 지적 근거를 대조해 정정하고 `any`용 `android-chrome-192x192.png`·`512x512.png`를 별도 생성해 `maskable`과 분리.
  - 중복 path 정리 중 `<use href="#head" fill="none"/>`가 `#head`의 직접 `fill` 속성을 덮어쓰지 못해 흰 배가 사라지는 회귀가 발생했고(테스트 전부 통과 상태), `opus`가 미리보기 PNG를 직접 보고 발견해 `<defs>` 분리 및 배 중심 픽셀 흰색 회귀 테스트를 추가.
  - `apple-touch-icon.png` 불투명 검증과 눈 채우기 `#f7d7a8` 반영.
- **v0.6.16 (PR #86, grok 구현, 배포 `ce710877`)**:
  - 배포 후 iPhone '홈 화면에 추가' 시 아이콘 미적용(사용자 보고, 이슈 #85). Cloudflare Access 뒤에서 iOS가 `apple-touch-icon`을 인증 쿠키 없이 요청해 302를 받는 것이 원인.
  - Access 정책 변경 없이 빌드 시 `vite.config.ts` `transformIndexHtml`로 `apple-touch-icon.png`를 data URI로 `index.html`에 인라인(`recompressPng` IDAT level 9 무손실 재압축 적용, `index.html` +14.5KB / gzip ~11KB).
  - 배포 후 사용자 iPhone 실기기에서 홈 화면 아이콘 적용 확인 OK(인증 브라우저 Chrome 확인은 사용자 요청으로 생략).
  - `hydro` 리뷰는 테스트가 `vite.config.ts` 플러그인 등록·예외 분기·`recompressPng`를 직접 검증하지 않는 점 등으로 `FIX` 판정 → 후속 이슈 #87로 분리.

## 2. 잘된 점
- **교차 리뷰의 실질적 품질 방어**: 1차 리뷰(`hydro`)가 `"any maskable"` 결합 문제, `apple` 불투명 검증 공백, 눈 색·path 중복을 정확히 짚었고, PR #86 리뷰에서도 테스트의 플러그인 연결 검증 누락을 찾아 #87로 이어졌다.
- **시각 산출물 직접 확인으로 회귀 조기 적발**: 기존 테스트가 모두 통과하던 상태에서 `opus`가 미리보기 PNG를 육안으로 확인해 흰 배 누락을 잡아내고, 픽셀 색 검증을 자동 회귀 테스트로 고정했다.
- **Access 무우회 원칙 유지**: Cloudflare Access에 공개 Bypass를 열지 않고 빌드 시 data URI 인라인으로 iOS 홈 화면 아이콘 제약을 해결해 사용자 실기기 검증까지 마쳤다.
- **재현 가능한 로컬 생성 파이프라인**: 외부 API나 추가 npm 패키지 없이 `scripts/generate-favicons.mjs`로 바이트 동일 재생성을 확보했다.

## 3. 문제와 근본 원인

### P1. 총괄(`opus`)의 잘못된 지시 전파 (`any` 파일 재사용 오판)
- **사실**: `hydro` 1차 리뷰 직후 `opus`가 `grok`에 "`any`에 같은 파일(`web-app-manifest-*`)을 재사용 가능하다"고 잘못 지시해 `grok`이 그대로 구현했다. 이후 `hydro` 지적 근거를 재확인해 `android-chrome-192x192.png`·`512x512.png`(`any`)와 `web-app-manifest-*`(`maskable`)를 분리했다.
- **근본 원인**: 총괄이 리뷰 지적의 기술 근거와 실물 여백 구조를 교차 확인하지 않은 채 단정적 구현 지시를 내렸다.
- **조치**: `herdr-orchestration` 스킬에 "`opus` 지시의 사실 주장도 틀릴 수 있으므로 리뷰어가 지시 자체도 근거와 대조해 독립 검증한다"는 규칙을 추가한다.

### P2. 테스트 전부 통과 상태에서 SVG 흰 배가 사라진 시각 회귀
- **사실**: `0a73bb1`에서 `#head` path 중복을 줄이기 위해 `<use href="#head" fill="none"/>`를 사용했으나 `#head` 원본 요소에 `fill="#e7b568"`이 직접 붙어 있어 덮어쓰지 못했고, 갈색 머리가 흰 배를 가렸다. 당시 테스트는 모두 통과 상태였고 `opus`가 미리보기 PNG를 열어보고 발견했다.
- **근본 원인**: 테스트가 PNG 크기·헤더·코너 불투명도만 검사하고 실제 아이콘 중심부 도형 렌더링을 검증하지 못했다. 시각 산출물은 수치 테스트만으로는 회귀를 놓치기 쉽다.
- **조치**: `#head`를 `<defs>`로 분리해 `fill`을 제거(`cf7c7c6`)하고, `apple-touch-icon.png` 배 중심 픽셀 흰색 검증을 테스트에 추가했다. `herdr-orchestration`에 시각 산출물 미리보기 직접 확인 게이트를 추가한다.

### P3. Cloudflare Access 뒤 iOS '홈 화면에 추가' 시 `apple-touch-icon` 미적용
- **사실**: `0.6.14`·`0.6.15` 배포 후 iPhone Safari에서 홈 화면에 추가할 때 아이콘이 적용되지 않았다(사용자 보고).
- **근본 원인**: Access가 정적 자산까지 인증 쿠키로 보호하는데, iOS 홈 화면 아이콘 로더는 `apple-touch-icon`을 쿠키 없이 요청해 302 로그인 리다이렉트를 받는다.
- **조치**: `0.6.16`에서 빌드 시 `apple-touch-icon.png`를 data URI로 `index.html`에 인라인하고(`recompressPng`로 크기 절감), 사용자 iPhone 실기기에서 정상 적용을 확인했다. `zzik-deploy`에 Access 뒤 정적 자산 처리 규칙을 반영한다.

### P4. 인라인 플러그인 테스트 공백 (`#87`)
- **사실**: `tests/ui/apple-touch-icon-inline.test.ts`가 순수 함수 `inlineAppleTouchIcon`만 호출해 `vite.config.ts` 플러그인 등록 여부·marker 부재 throw·`recompressPng` 직접 단위 검증이 빠졌음이 `hydro` 리뷰에서 지적됐다.
- **근본 원인**: 단위 테스트 대상을 순수 문자열 변환 함수로 한정하고 Vite 설정 연결 및 보조 모듈 테스트를 생략했다.
- **조치**: 후속 이슈 #87로 분리해 테스트를 보강하기로 했다.

### P5. 운영·CLI 잡음 (`herdr` 플래그, DB 게이트 리포터, `.vitest/` 잔여물)
- **사실**:
  1. `herdr agent prompt --timeout`을 `--wait` 없이 사용해 `exit 2`로 전송되지 않았다.
  2. `sol`이 배포 전 DB 게이트를 JSON 리포터로 읽어 판독에 실패해 일시 중단했다가, 스킬 기본 명령으로 재실행해 `PASS`를 확인했다.
  3. 테스트 실행 잔여물 `.vitest/`가 `.worktree/release`를 dirty 상태로 만들어 정리했다.
- **근본 원인**: 스킬에 적힌 명령·플래그를 임의 변형했고, 테스트 실행 뒤 워킹트리 잔여물 정리를 놓쳤다.
- **조치**: `herdr-orchestration`에 `--timeout`+`--wait` 규칙을, `zzik-deploy`에 DB 게이트 기본 명령 준수 및 `.vitest/` 등 잔여물 정리 규칙을 추가한다.
