# 부검·회고: 트렌드 수집 중단·models.dev 링크·속성명 말풍선 (0.6.50~0.6.52)

- **일자**: 2026-11-19
- **대상**: v0.6.50(`0f28ded`), v0.6.51(`9cf0d1b`), v0.6.52(`e65a2ba`). 이슈 #116 마무리와 #107·#109·#115·#131 정리, 위키 v0.6.17 → v0.6.52 동기화
- **워커 구성**: z-opus(총괄), z-sol(Codex `GPT-6.2-Sol`), z-fable(Claude Code `Fable 5.1`), z-hyd(Antigravity `Gemini 4 Hydrogen`), z-glm(OpenCode Go `GLM-5.3`, 이번 세션 신규)
- **결과**: 세 patch 모두 배포 게이트 PASS. 전체 테스트 2,629건. 배포 직후 공개 트렌드 네 섹션이 `stale` → `ok`. 말풍선은 WebKit 390px 합성 fixture로 확인했고 실기기 확인은 사용자에게 Discord로 요청했다.

## 1. 타임라인 및 결과 요약

- **배치**: 워크스페이스를 새로 열어 z-opus 라벨링 후 z-fable·z-sol·z-hyd·z-glm 탭을 띄웠다. OpenCode는 실행 인자로 모델을 받지 않아 `-m` 전달 시 시작이 타임아웃 났고, 기본 모델로 띄운 뒤 `/models`에서 OpenCode Go `GLM-5.3`을 골랐다.
- **분배**: 트렌드 미갱신·4시간 주기는 z-sol(`0.7/trend-4h`), models.dev 링크는 z-hyd(`0.7/links-modelsdev`), Safari 툴팁은 z-fable(`0.7/safari-tooltip`). 작업마다 worktree와 `worker-watcher`를 하나씩 붙였다. 이슈 판정은 z-glm(읽기 전용), 위키는 z-hyd(변경 이력)·z-glm(아키텍처·배포 운영·Home)이 각자 클론에서 나눴다.
- **트렌드 원인**: 크론은 돌았지만 공통 HTTP 함수가 `options.fetchImpl(...)`로 네이티브 fetch를 불러 `this`가 옵션 객체가 됐다. workerd에서 `Illegal invocation`이 나 모든 업스트림 요청이 `network`·`http_status=null`로 기록됐고, 11월 17일 이후 섹션이 갱신되지 않았다. `fetchImpl.call(globalThis, …)`로 고치고 cron을 `7 */4 * * *`, stale 기준을 2×주기(8시간)로 맞췄다(`fa6e567`).
- **툴팁**: 처음엔 직전 수정인 트리맵 툴팁으로 지시했다. 사용자가 "사용량에서 속성 보여주는 툴팁"이라고 정정해 `RawIdInfo`로 바꿨다. 원인은 Safari 고유 버그가 아니라 640px 미만 목록 모드에서 머리글이 숨겨지며 첫 행 말풍선이 표 래퍼 `overflow-hidden` 밖으로 나가는 클리핑이었다. body 포털·`position: fixed`로 옮겼다(`85e759d`). z-sol 교차 리뷰가 아래 공간 미확인, 레이아웃 변경 시 좌표 고정, 헤더 뒤로 가려진 버튼의 말풍선 노출 3건을 잡아 `2588ae2`로 반영했다.
- **배포**: 0.6.50은 한 번에 통과. 0.6.51 첫 `ship.mjs --apply`는 `release_prep`의 KST 전체 테스트에서 실패했다(아래 P1). 테스트를 고쳐 재실행해 통과했고 `trend_refill`이 섹션을 채웠다. 0.6.52는 README 갱신과 함께 통과.
- **정리**: 열린 이슈 5건을 근거 커밋과 함께 닫았다. 위키는 v0.6.17 이후 33개 버전이 비어 있어 한 번에 채웠다.

## 2. 잘된 점

- **실측으로 원인 확정**: z-sol이 운영 D1과 공개 API를 읽기 전용으로 대조해 "크론은 진입, 출처 요청은 전부 실패"를 시각까지 맞췄고, 같은 호환성 날짜의 workerd로 `Illegal invocation`을 재현했다. 추측 수정이 아니었다.
- **교차 계열 리뷰가 실제로 걸렀다**: Anthropic 구현(z-fable)을 OpenAI(z-sol)가 리뷰해 포털 전환 뒤 생긴 경계 3건을 배포 전에 잡았다.
- **patch 단위 배포**: 링크·트렌드·툴팁을 각각 배포해 실패 범위가 0.6.51 하나로 좁혀졌다.
- **문서 분할**: 위키를 클론 두 개로 나눠 파일 충돌 없이 병렬로 쓰고 총괄이 합쳐 푸시했다. 합치는 과정에서 무료 모델 범위(Ollama Cloud 제외) 오기재를 잡았다.

## 3. 문제와 근본 원인

### P1. 공유 상수 변경이 다른 디렉터리의 테스트를 깨뜨림

- **사실**: z-sol은 `TREND_SECTION_STALE_MS`를 4시간에서 8시간으로 바꾸며 트렌드 관련 테스트 16개 파일을 돌렸다. `tests/worker/ui/trend-route.test.ts`는 "5시간 경과면 stale"을 단언하고 있었는데 대상에서 빠졌다. 릴리스 준비의 KST 전체 테스트에서 처음 실패했고 `fcb7f04`로 9시간으로 고쳤다.
- **근본 원인**: "관련 테스트"를 파일 경로·이름으로 골랐다. 상수 값을 숫자 리터럴로 다시 쓴 테스트는 import 그래프에도 이름에도 걸리지 않는다.
- **조치**: `shared/` 상수·기준값을 바꾸면 상수 이름과 이전 값(예: `4 * 60 * 60`)을 `tests/` 전체에서 grep해 걸린 파일을 함께 돌린다. 테스트는 기준값을 리터럴로 다시 쓰지 않고 상수에서 유도한다. `layered-tdd`에 반영.

### P2. 릴리스 준비 실패가 생성 파일을 남겨 재실행을 막음

- **사실**: `release_prep`은 버전을 0.6.51로 올리고 README 스크린샷 3개를 다시 찍은 뒤 테스트에서 멈췄다. 메인 작업 사본이 dirty라 `worktree_clean`이 재실행을 막았다. 총괄의 `git checkout -- .` 일괄 원복은 자동 권한 검사에서 거부됐고, diff를 확인한 뒤 해당 4개 파일만 `git restore`로 되돌렸다.
- **근본 원인**: 실패 시 정리 책임이 스크립트에 없다. 일괄 원복은 무엇을 지우는지 보이지 않아 위험 작업으로 분류된다.
- **조치**: 실패 후 복구 절차를 `zzik-deploy`에 적는다 — `git status`로 생성 파일(`package.json`, `docs/screenshots/desktop.png`, `public/screenshots/*`)만 남았는지 확인하고 그 경로만 `git restore`한 뒤 재실행. 스크립트 자동 정리는 후속 과제로 둔다.

### P3. UI 대상을 묻지 않고 가정함

- **사실**: "Safari에서 여전히 툴팁이 가려짐"을 받고 직전 수정(#131 트리맵)으로 지시했다. 사용자 정정으로 z-fable이 중간에 대상을 바꿨다.
- **근본 원인**: "여전히"를 직전 커밋과 연결했다. 기존 메모리 규칙(재현 전 어느 컨트롤인지 확인)을 지키지 않았다.
- **조치**: UI 버그는 화면·컨트롤을 특정할 수 없으면 워커 배정 전에 한 줄로 묻는다. 규칙은 이미 있으므로 새로 적지 않고 이 회고에 기록만 한다.

### P4. 트렌드가 이틀 넘게 stale인데 아무도 몰랐음

- **사실**: 공개 인덱스는 11월 17일부터 섹션을 `stale`로 표시했지만 경보가 없었다. 사용자 보고로 알았다.
- **근본 원인**: 단위 테스트가 주입한 가짜 fetch만 써서 네이티브 수신자 문제를 볼 수 없었고, 운영 상태(`stale`)를 감시하는 경로가 없었다. `ship` 재적재는 Node 경로라 Worker 런타임 결함을 가렸다.
- **조치**: workerd 회귀 테스트(`tests/worker/trend.workerd.test.ts`)를 추가했다. 섹션 stale 경보는 #141로 열었다.

### P5. 작업·문서 기록 누락

- **사실**: 세 수정은 이슈 없이 진행됐다(`herdr-orchestration`의 "작업 단위마다 이슈"). 위키는 4일·33개 버전 동안 갱신되지 않았다. OpenCode 모델 지정 방법, z-glm·`GPT-6.2-Sol` 구성도 문서에 없었다.
- **근본 원인**: 위키 갱신이 릴리스 절차 밖에 있다. 신규 워커를 띄울 때 구성 문서를 함께 고치는 단계가 없다.
- **조치**: 세 수정의 기록 이슈(#138·#139·#140)를 만들어 닫았다. 위키 변경 이력 갱신을 `zzik-deploy` 릴리스 묶음 마무리에 넣는다. `docs/harness/agents.md`에 z-glm과 OpenCode 모델 선택 방법을 적는다.
