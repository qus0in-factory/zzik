## 1. 타임라인 및 결과 요약

- **배치**: 새 워크스페이스에서 z-opus 라벨링 뒤 사용자 요청이 연달아 들어와 z-glm·z-ds·z-argon·z-sonnet·z-beam·z-hf를 차례로 열었다. OpenCode는 기본 모델로 띄운 뒤 `/models`에서 공급자 열을 보고 골랐고, agy는 `herdr agent start … -- --model <ID>`로 바로 열었다. `z-bf`는 이름만으로 모델을 추정해 열었다가 사용자 정정으로 닫았다.
- **문서**: `docs/harness/agents.md`를 "현재 가동 구성"에서 "띄울 수 있는 후보 풀"로 바꿨다. 열린 패널은 `herdr agent list`가 정본이고, 열고 닫을 때 문서를 고치지 않는다(`4ada3bc`).
- **분배(1차)**: 출력 단가 20은 z-hf, 접기 기억은 z-sonnet, 버전명은 z-argon. 작업마다 worktree와 `worker-watcher`를 하나씩 붙였다.
- **분배(2차, 사용자 "남은 애들 나눠서")**: z-glm 배포분 리뷰, z-sonnet 트렌드 패널 화면 점검, z-beam 문서 동기화, z-hf 라벨 스크립트 agy Sonnet·Opus 감지. 이 점검에서 비용 표 모바일 끊김(z-sonnet 수정), 인용 모델명 줄 경계 분리(z-argon 수정), 측정 스크립트 옛 경로(z-hf 수정)가 나왔다.
- **배포**: 0.6.54 접기 기억, 0.6.55 단가 20(트렌드 재적재·수집기 반영 포함), 0.6.56 버전명·비용 표 줄바꿈·문서·라벨 스크립트. 모두 한 번에 통과했다. 0.6.56 재적재 직후 운영 `/pub/trend/metrics` 문장이 "요즘 주목받는 모델은 Claude Fable 5.2, Claude Opus 5.5, Gemini 4 Carbon, Gemini 4 Neon, GPT 6.2 Astra, GPT 6.2 Sol 등입니다."로 바뀐 것을 확인했다.

## 2. 잘된 점

- **검수 통과 조각부터 배포**: 세 기능을 각각 patch로 내보내 사용자 확인 요청도 기능별로 분리됐다.
- **놀리지 않는 분배**: 구현이 끝난 워커에 바로 리뷰·화면 점검·문서를 맡겨 후속 결함 3건을 배포 전에 잡았다. 화면 점검은 실제 수치(scrollWidth, 줄 수)로 보고돼 판단이 빨랐다.
- **공개 문구 규칙 유지**: 버전명을 넣으면서도 순위·점수 단어 금지, 계열당 하나, 저장된 옛 문장 통과를 테스트로 고정했다. 계열 키는 버전을 뺀 이름으로 따로 계산한다.
- **문서 유연화**: 후보 풀 방식이라 이번 세션의 패널 6개 개폐 동안 문서 수정이 다시 필요하지 않았다.

## 3. 문제와 근본 원인

### P1. 첫 지시가 OpenCode 선택 창에 삼켜짐

- **사실**: z-hf에 모델을 고른 뒤 `Select variant` 창이 열린 채였다. 보낸 지시문이 창 검색칸에 들어가 "No results found"로 사라졌고, watcher가 결과 파일 없이 `agent_idle`을 보고해 알았다. 창을 닫고 재전송했다.
- **근본 원인**: 모델 선택 확인을 상태줄 한 줄 grep으로 했다. 창 뒤에 깔린 상태줄이 잡혀 창이 열린 것을 놓쳤다. z-ds는 같은 창을 화면 전체로 읽어 발견했지만 z-hf에는 같은 확인을 하지 않았다.
- **조치**: 첫 지시 전에 화면 전체를 읽어 선택 창이 없는지 확인한다. `herdr-orchestration`에 반영.

### P2. 짧은 에이전트 이름을 추정해 잘못 엶

- **사실**: "z-beam, z-bf 열기"를 z-beam=Ollama Cloud `beam`, z-bf=OpenCode Go `Beam Free`로 추정했다. 사용자 의도는 z-beam=OpenCode Go였고 z-bf는 필요 없었다.
- **근본 원인**: 구성 문서에 없는 이름을 모델 목록 문자열에서 끼워 맞췄다.
- **조치**: 후보 풀 표에 z-beam·z-sonnet·z-argon을 올려 다음부터는 표를 따른다. 표에 없는 이름은 여는 데 드는 비용이 작으므로 추정해 열되, 공급자를 결과 보고에 명시해 바로 정정할 수 있게 한다.

### P3. TDD red 단계 생략

- **사실**: z-sonnet은 접기 기억 테스트를 구현과 함께 작성해 실패 확인을 하지 않았다고 보고했다. z-hf·z-argon은 기대값 테스트를 먼저 바꿔 red를 확인했다.
- **근본 원인**: 지시문에 "테스트 먼저"만 있고 실패 확인 보고를 요구하지 않았다.
- **조치**: 이번 변경은 리뷰(z-glm)와 화면 점검으로 보완했다. 규칙은 이미 `layered-tdd`에 있으므로 새로 적지 않고 기록만 한다.

### P4. 점검 도구가 대상 화면을 덮지 못함

- **사실**: `scripts/ui-overflow-check.mjs`는 `/usage` 트렌드 패널(펼친 AA 표)을 다루지 못해 z-sonnet이 임시 `check.mjs`를 만들었다. `scripts/measure-layout.mjs`·`capture-motion-frames.mjs`는 `/usage` 분리 이후에도 `/?fixture=`를 가리키고 있었다. AA fixture는 모델이 12개뿐이라 20행 표시를 확인할 수 없었다.
- **근본 원인**: 라우트 분리 때 스크립트 경로를 함께 grep하지 않았고, fixture 크기가 표 상한 변경을 따라가지 않았다.
- **조치**: 두 스크립트 경로를 `/usage?fixture=`로 고쳤다. 트렌드 패널 펼침 케이스 추가와 AA fixture 20개 이상 확대는 남은 일로 둔다.

### P5. 배포 중 병합 대기

- **사실**: `ship.mjs`가 dev에 릴리스 커밋을 만드는 동안 끝난 워커 결과가 들어와 병합을 미뤘다.
- **근본 원인**: 배포와 병합이 같은 dev 체크아웃을 쓴다.
- **조치**: ship 진행 중에는 병합하지 않고 끝난 뒤 묶어 병합한다. `herdr-orchestration`에 명시.
