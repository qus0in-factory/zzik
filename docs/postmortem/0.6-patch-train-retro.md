# 부검·회고: 0.6.x patch 연속 배포와 0.7 기능(차트·알림·하트비트)

- **일자**: 2026-11-14
- **대상**: v0.6.1 ~ v0.6.11 (PR #64~#75), 이슈 #47 차트, #63 알림, #70 하트비트, #74 Grok 토큰
- **작성자**: opus

---

## 1. 결과 요약
- 하루 동안 patch 11회를 배포했다. 배포 단위는 "검수 통과한 가장 작은 조각"이었다.
- 기능
  - 사용량 추이 차트(uPlot, 지연 로드)와 범례 토글을 넣었다. 범례 상태는 브라우저별로 저장한다.
  - 캐시는 IndexedDB·localStorage·TanStack을 쓴다.
  - 그리드·목록 보기를 전환할 수 있다.
  - 제공자 사용량 페이지 링크를 붙였다.
  - 추가 지출(extra_usage)을 화면에서 제거했다.
  - 변화 없는 제공자에 하트비트 이력을 남긴다.
  - 사용량 상태 변화를 Discord로 알린다.
- 하네스
  - 전역 스킬과 서브에이전트를 symlink로 공유한다.
  - Discord와 이미지 생성 스킬을 전역화했다.
  - 워커 구성을 바꿨다. grok·hydro·argon·sonnet·hy·glm은 닫고 beam을 추가했다. sonnet은 서브에이전트로 쓴다.

## 2. 잘된 점
- **patch 단위 배포**: 사용자가 "빨리 끊어서 배포"를 요청한 뒤 대기 시간이 크게 줄었다. 비핵심(UI·문서)은 테스트·빌드만 통과하면 먼저 배포하고 리뷰는 나중에 했다. 미뤄 둔 리뷰(glm)에서 차단 항목은 0건이었다.
- **교차 리뷰의 가치**: #63 알림에서 glm은 "차단 없음"으로 봤지만, fable은 이른 0% 리셋 참조로 생기는 가짜 리셋·가짜 해제를 재현했다(R1). 리뷰어를 둘 둔 덕에 잡혔다.
- **실데이터로 원인 확인**: Ollama 차트가 열리지 않은 원인을 운영 DB 읽기 전용 건수 조회로 바로 찾았다. 이력이 0건이었고, 변화가 있을 때만 쓰는 구조 때문이었다. 0.3 부검의 "실데이터 대조" 교훈이 지켜졌다.
- **위험한 변경은 조사 먼저**: Grok 토큰 자체 갱신(#74)은 구현 전에 조사 ADR(0.9)을 썼다. refresh token 회전 때문에 OpenCode 로그인을 깰 수 있다는 근거로 현행 유지를 결정했다.

## 3. 문제와 근본 원인

### P1. release 워크트리에 인증 우회 패치가 남음 (위험도 높음)
- **사실**: beam이 화면을 찍으려고 `.worktree/release`의 `worker/ui/router.ts`를 `auth = { ok: true }`로, `worker/index.ts`도 함께 고쳤다. 재촬영 뒤 원복하지 않았다. opus가 원복했고, 운영 배포에는 포함되지 않았다.
- **원인**: 화면 확인 절차가 배포용 워크트리를 그대로 썼다. 원복 확인이 워커의 자기 보고에만 의존했다.
- **조치**
  - `zzik-deploy` 스킬에 "release 워크트리 임시 패치 금지, 별도 임시 워크트리 사용, 배포 전 `status --short` 비어 있음 확인"을 추가했다.

### P2. 워커 보고와 실제 결과 불일치
- **사실**: beam이 "Ollama 차트 열림"이라고 보고했지만 스크린샷에는 닫혀 있었다. 버튼이 aria-disabled인 상태에서 찍혔다.
- **원인**: 스크린샷을 찍기 전에 비동기 요약 응답을 기다리는 조건이 없었다.
- **조치**: opus가 스크린샷을 직접 열어 판정하는 규칙(메모리 `deploy-browser-verify-self`)을 유지한다. 지시에 "버튼 활성화와 차트 렌더를 기다린 뒤 촬영"을 명시한다.

### P3. `.env` 끝 줄바꿈 누락으로 줄이 붙음
- **사실**: `ZZIK_ALERT_WEBHOOK_URL`을 `>>`로 덧붙였는데, 마지막 줄 끝에 줄바꿈이 없어 `GEMINI_API_KEY` 줄 뒤에 이어 붙었다. 바로 분리해 복구했다(값은 출력하지 않음).
- **원인**: 덧붙이기 전에 파일 끝 문자를 확인하지 않았다. release `.env`가 루트 `.env`로 가는 symlink라는 점도 놓쳤다.
- **조치**: `.env`에 덧붙일 때는 `tail -c1`로 끝 문자를 확인하고, 필요하면 줄바꿈부터 넣는다. 수정 뒤에는 키 이름 목록만 출력해 검증한다. 이 내용을 `zzik-deploy` 스킬에 반영했다.

### P4. 변화 기반 이력 쓰기와 화면 조건의 불일치
- **사실**: 이력은 값이 바뀔 때만 썼다. 반면 차트 열림 조건은 "ok 2건 이상 + 6시간"이었다. 값이 고정된 Ollama는 영원히 열리지 않았다.
- **원인**: 저장 정책(ADR 0.5)과 화면 조건(ADR 0.7)을 따로 설계했다. 두 문서를 교차해 확인하지 않았다.
- **조치**: 6시간 하트비트(#70)를 넣고 열림 조건을 ok 1건으로 바꿨다. ADR 0.7을 갱신했다.

### P5. 병합 충돌과 동시 브랜치
- **사실**: extra-usage와 chart-ko는 차트 화면 쪽에서, heartbeat와 alerts는 수집기 쪽에서 충돌했다.
- **조치**: 수집기 핵심 경로의 충돌은 opus가 직접 풀지 않고, 두 기능의 구현자(sol)에게 merge로 해결하게 했다.
- **교훈**: 같은 파일을 건드리는 브랜치는 직렬화하거나, 앞 브랜치가 병합된 dev에서 다음 브랜치를 딴다.

### P6. 사용자 요청 해석
- "추가 사용량 안 보이게"를 처음에는 "한도 카드·차트에서만 분리하고 별도 행으로 표시"로 구현했다. 사용자는 화면에서 완전히 없애길 원했다(v0.6.9).
- **교훈**: "안 보이게"는 말 그대로 완전 제거로 해석한다. 정보 보존이 필요하면 수집·도메인 계층에만 남긴다.

## 4. 남은 위험·후속
- #63 알림은 첫 실전송을 아직 확인하지 못했다. 다음 상태 변화나 최상위 한도 리셋 때 확인한다.
- 알려진 한계
  - 상태 파일 쓰기에 실패하면 하트비트가 중복으로 기록될 수 있다.
  - 제공자가 resetsAt를 늦추면 리셋 문구가 잘못 붙을 수 있다.
  - 예전 기준선에서는 해제 알림이 1주기 늦는다.
- Grok(xAI) 토큰은 OpenCode가 갱신을 소유한다. 만료되면 OpenCode에서 xAI를 한 번 사용한다(ADR 0.9).
- 정리 후보: 도메인에 남은 extraSpend 체인과 `label.extraUsage` 문구. 화면에서는 쓰지 않는다.
