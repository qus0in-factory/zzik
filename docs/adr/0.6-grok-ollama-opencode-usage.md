# ADR 0.6: OpenCode · Grok · Ollama 사용량 (저장소 무관 부분)

상태: 브랜치(`0.6/providers`) 구현 완료, **운영 검증 대기**. 이 작업에서는 배포·KV 쓰기·PM2 재시작을 하지 않는다. 저장소 계층(Postgres 전환, 브랜치 `0.5/postgres`)은 건드리지 않는다. 설계 정본은 /tmp/fable-grok-ollama-opencode.md, 조사 근거는 /tmp/gemini-grok-ollama-opencode.md다. ~/Factory/biseo는 읽기만 했다.

## D1. 이름·순서·설정

| 항목 | 결정 |
|---|---|
| provider id | `opencode`, `grok`, `ollama` |
| 순서 | claude, codex, antigravity, opencode, grok, ollama(shared·collector·src 일치 테스트) |
| 상태 파일 | `usage-state.{opencode,grok,ollama}.json` |
| KV 키(0.5 전까지) | `usage:{opencode,grok,ollama}` — 0.5/postgres가 `USAGE_KV_KEYS`를 삭제하면 병합 때 이 항목도 함께 사라진다 |
| collector version | 0.6.0 |
| env | `ZZIK_OPENCODE_DB_PATH`(기본 `~/.local/share/opencode/opencode.db`), `ZZIK_OLLAMA_HOST`(기본 `http://127.0.0.1:11434`) |
| ecosystem | 이 브랜치는 `ZZIK_PROVIDERS`를 바꾸지 않는다. 제공자별 G2a 기록 뒤 하나씩 추가 |

## D2. 읽기 전용 자격 증명

- OpenCode·Grok: `node:sqlite` `DatabaseSync(path, { readOnly: true })`로 `credential` 표를 `integration_id`(`opencode`/`xai`) 조건, `time_updated` 내림차순 5행까지 읽고 `access`가 비어 있지 않은 첫 행을 쓴다. `expires`(Unix ms)가 유한 숫자면 `expiresAt`, 아니면 null. `refresh`와 그 밖의 키는 꺼내지 않는다. 열기·질의 실패는 200ms 뒤 1회 재시도 뒤 null(`no_credentials`). 권한 경고는 프로세스당 1회. 갱신 소유자는 OpenCode이고 수집기는 쓰지 않는다. `auth.json`은 읽지 않는다.
- Ollama: 토큰이 없다. 항상 토큰 없는 읽기 1건을 돌려 run-once 흐름을 그대로 타고, 클라이언트는 Authorization 헤더를 보내지 않는다.

## D3. 요청·분류

| 제공자 | 요청 | 비고 |
|---|---|---|
| OpenCode | `GET https://opencode.ai/zen/go/v1/usage` | Authorization, Accept만 |
| Grok | `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits` | 아래 예외 #2 헤더 |
| Ollama | `GET <ZZIK_OLLAMA_HOST>/api/balance` | 3초 타임아웃, loopback `http`만 허용(그 외 기동 시 종료 78) |

세 클라이언트는 `fetch-usage-json.mjs` 하나로 ADR 0.3 D4 분류표를 공유한다(`redirect: 'manual'`, 10초(Ollama 3초), 실패 본문 미보관). 데몬이 꺼진 Ollama는 `network_error`로 올라가며 새 상태 값은 만들지 않는다(화면 문구만 `networkErrorNote`로 제공자별 교체).

**ADR 0.3 D4 예외 #2(사용자 승인, 2026-11-13):** Grok 요청에 클라이언트 식별 헤더 `X-XAI-Token-Auth: xai-grok-cli`, `x-grok-client-version: 1.0.0`을 붙인다. 공식 grok CLI로 자신을 알리는 헤더이며 프록시가 요구한다(예외 #1은 Antigravity UA, 0.4). 값은 상수(`GROK_CLIENT_HEADERS`, 동결)로 고정하고 env로 바꿀 수 없다. 다른 제공자의 헤더 정책은 바꾸지 않는다.

가림 목록: Grok `config.topUpMethod`(결제 수단 식별자일 수 있는 자유 문자열, 화면 미사용). OpenCode·Ollama는 빈 목록.

## D4. 프론트 카드 매핑

- Grok: `config.creditUsagePercent` → 카드 1장(`credits`). 라벨은 `currentPeriod.type` 표(주간/월간 크레딧, 모르면 "크레딧 사용률"+미확인), 주기는 `billingPeriodEnd − billingPeriodStart`. `config`가 없으면 루트로 대체하지 않고 `invalid_shape`.
- OpenCode: `usage`의 모든 키를 카드로. 표 순서 rolling → weekly → monthly(단기/주간/월간 한도), 모르는 키는 뒤에 알파벳순+미확인. 주기는 weekly만(604800초). `status` 필드는 무시.
- Ollama: `(allowance_usd − balance_usd) / allowance_usd`를 퍼센트로(정밀도 유지) "포함 크레딧" 카드 1장, 주기는 `until − from`. `purchased`는 카드 없이 `others`에 보존.
- DEV 날짜 보정은 `rebaseIsoFields(raw, keys, from, to)`로 일반화했고 Antigravity 호출부는 같은 동작의 래퍼다.

## 검증

G2a dry-run 1회씩 성공([기록](../research/0.6-g2a-providers.md)). 라벨·매핑은 조사 보고서의 마스킹 형상 기준 "잠정"이며, 첫 쓰기 뒤 live-shape로 확정(G2b)한다. 배포·KV 쓰기·PM2는 이 작업 범위 밖.
