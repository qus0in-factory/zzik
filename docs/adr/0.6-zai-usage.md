# ADR 0.6: Z.AI 사용량

2026-11-21 결정: 사용량 제공자 `zai`(Z.AI GLM Coding Plan)를 추가한다. 아래 응답 형태는 이날 실측 기준이다. 키·실측 값은 이 문서에 기록하지 않는다.

상태: 문서 트랙(브랜치 `0.6/zai-docs`) 문서화. 수집기 트랙(z-sol)·웹 트랙(z-fable)이 이 결정으로 구현을 병행한다. 이 문서 트랙은 코드·테스트를 고치지 않고 배포·D1 쓰기·PM2 재시작도 범위 밖이다.

## D1. 이름·순서

| 항목 | 결정 |
|---|---|
| provider id | `zai` |
| 카드 표시명 | Z.AI |
| 순서 | claude, codex, antigravity, opencode, grok, ollama 뒤 |

## D2. 읽기 전용 자격 증명

- OpenCode DB(기본 `~/.local/share/opencode/opencode.db`, env `ZZIK_OPENCODE_DB_PATH`)의 `credential` 표에서 `integration_id`가 `zai-coding-plan`인 value `{type:"key",key}` API 키를 읽는다.
- 읽기 전용이다. 갱신 소유자는 OpenCode이고 수집기는 키를 갱신하지 않는다(0.6 OpenCode·Grok·Ollama ADR D2와 같은 규칙).

## D3. 요청

| 항목 | 결정 |
|---|---|
| 요청 | `GET https://api.z.ai/api/monitor/usage/quota/limit` |
| 인증 | `Authorization: Bearer <key>` |

공식 문서 없는 비공식 엔드포인트다(서드파티 도구들이 사용). 예고 없이 형태가 바뀔 수 있어 D4의 무시 규칙으로 대비한다.

## D4. 응답·해석 (2026-11-21 실측)

- `data.limits[]`에서 type `CREDIT_LIMIT` 두 항목을 읽는다. unit 3·number 5는 5시간 창, unit 6·number 1은 주간 창이다.
- 항목 필드: `usage`(창 한도), `currentValue`, `remaining`, `percentage`, `nextResetTime`(Unix ms). `data.level`은 요금제다.
- 모르는 type·unit 항목은 무시한다. 형태가 아예 다른 응답은 기존 사용량 분류(ADR 0.3 D4)를 따른다.
- 가림 목록: `[]`(응답에 식별자가 없다).

## D5. 표시

- `/usage`에 Z.AI 카드를 추가한다. 5시간 창·주간 창의 사용률(`percentage`)과 각 창의 초기화 시각(`nextResetTime`)을 보여 준다.

## 검증

- 구현·검증은 병행 트랙이 맡는다: 수집기 z-sol(자격 증명·요청·상태 저장), 웹 z-fable(`/usage` 카드 매핑).
- 이 문서는 결정 정본이며, 실제 키·응답 값은 어느 문서에도 남기지 않는다.
