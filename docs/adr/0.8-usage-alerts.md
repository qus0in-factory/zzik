# ADR 0.8 — 수집 주기의 사용량 변화 알림 (#63)

상태: 구현. 운영 반영·수집기 재시작은 별도 승인 뒤 진행한다. 런타임은 **Node 24.22+**를 요구한다(`shared/*.ts`를 네이티브로 직접 import).

## 판정과 저장

- `collector/domain/usage/alert-report.mjs`가 `shared/usage-scan`으로 성공한 원문에서 모든 창·metric을 읽는다. 원문·자격 증명은 이벤트에 넣지 않는다. 실패·게이트 건너뜀·판독 실패는 회복으로 보지 않고 이전 알림 상태를 보존한다. 누락된 창도 자동 정상 해제로 해석하지 않는다.
- 대시보드의 `barLevelOf`·`getUsageStatus`·`elapsedPercent` 및 요약 창 선택을 `shared/usage-policy.ts`로 옮겨 화면과 수집기가 같은 함수를 사용한다. 주의는 기간 경과율보다 빠른 사용(주기를 모르면 70% 이상), 위험은 90% 이상, 한도 도달은 100% 이상이다. 0%와 여유는 정상이다. 알림 전용 `ALERT_CAUTION_MIN_PERCENT=25` 하한을 두어 주의는 사용률 25% 이상일 때만 보낸다. 위험·한도 도달에는 이 하한을 적용하지 않는다. 기존 화면의 판정과 공개 시그니처는 유지한다.
- app의 순수 `diffAlerts(prevState, nextReport)`가 진입·악화·정상 해제·리셋 이벤트를 만든다. 시계는 report.nowMs로 주입한다. `nextAlertState`는 마지막 관측 값·레벨 및 마지막 알림 시도 레벨·시각을 만든다.
- 최상위 주기는 **cycleSeconds만** 기준으로 월간(28~31일) 우선, 없으면 주간이며 동률이면 사용률이 높은 창이다. id/라벨이 monthly여도 cycleSeconds가 null이면 월간으로 추정하지 않는다(OpenCode resetsAt 누락 포함). Claude scoped metric은 제외하고 Antigravity는 Gemini 창만 선택한다.
- 저장된 resetsAt이 지났고 현재 값이 새 관측(만료되지 않은 값 또는 확인된 0%)이며 사용률이 이전 주기 기준보다 하락하면 새 주기로 판정한다. **정확히 0%일 필요는 없다**(0.4% 등 포함). 최상위 창이면 현재 사용률을 포함한 “주기 리셋” 1건으로 보고하고 그 창의 N을 정상, 쿨다운을 빈 값으로 되돌린다. 일반 해제와 중복하지 않는다. 다른 창(5시간 등)은 N이 경고 단계였을 때 일반 해제 1건만 보고한다. 만료된 옛 양수·리셋 전 감소·하락 없는 관측은 리셋으로 만들지 않는다.
- reset 이벤트의 from/to는 `previous_cycle → new_cycle`이며, 직전 알림 레벨은 previousLevel로 별도 보존한다. 메시지는 직전 경고가 있으면 “위험 → 정상” 등을, N이 이미 정상이면 “이전 주기 → 새 주기”를 표시한다. 정상 N의 실제 리셋도 정상→정상 이벤트 없이 알릴 수 있고 모든 이벤트의 from과 to가 다르다.
- 이른 0%가 원래 리셋 전에 오면 현재 사용률은 관측값으로 갱신하되, 원래 시각과 하락 전 사용률을 `resetReference`로 보존한다. 제공자가 다음 resetsAt을 일찍 바꿔도 이 저장 경계가 경과하기 전에는 리셋을 알리지 않는다. 실제 경과 후 0% 또는 소수 사용률을 관측하면 리셋 1건을 보고하고 참조를 비운다. 만료 양수는 보류하되 이후 확인된 0%는 시각 미갱신 상태에서도 검출한다.
- 첫 성공 판독은 현재 상태를 기준선으로만 저장한다. 최초 주의/위험/한도 기준선에는 시작 시각도 저장해 해제·완화에 30분 쿨다운을 적용한다. 이후 새 창은 정상에서 시작한 것으로 비교한다. 재시작 시 기존 `usage-state.<provider>.json`의 `alerts`(version=1)를 읽는다. 없는/손상된 알림 상태는 첫 기준선을 다시 만든다. 기존 previous·인증 게이트와 함께 저장하며 추가 상태 파일은 없다.
- 사라진 창은 `ALERT_MISSING_MAX_CYCLES=96`회의 성공 관측에서 연속 누락되면 체크포인트와 오래된 primary 참조를 정리한다(900초 기준 약 24시간). 재등장하면 누락 횟수를 0으로 되돌린다. 수집 실패·판독 실패·DB 저장 실패 주기는 누락 횟수를 늘리지 않는다.
- 전이는 **마지막으로 알린 레벨 N만** 기준이다. to=N이면 이벤트 없음. 낮아지는 해제·완화와 정상에서 주의 진입은 30분 쿨다운 뒤에만 보고한다. 기존 경고에서 더 높은 단계로의 악화와 정상에서 위험·한도 도달 진입은 즉시 보고한다. 관측 레벨 상승을 별도 이벤트 조건에 섞지 않는다. 억제 시 관측 값만 갱신하고 N은 유지한다. 수집 주기 때문에 쿨다운 뒤 실제 관측까지 보통 30~45분 걸릴 수 있다.


## 전송과 실패 경계

- 제공자별 성공 저장 뒤 기준선을 체크포인트하고 `runCycle`이 모든 제공자의 이벤트를 한 메시지로 묶어 infra Discord 포트에 전달한다. DB 저장에 실패하면 알림 기준선을 진전시키거나 이벤트를 전송하지 않는다. 상태 파일 저장은 try로 감싼다. 실패하면 전송을 억제하고 종료 코드 4를 반환하지만 제공자 로그 한 줄은 남긴다(`state=fail`, 오류 원문 없음). DB 성공 여부는 kv=ok/fail로 별도 표시하므로 DB 저장 성공과 로컬 상태 실패를 구분할 수 있다.
- `.env`의 전용 `ZZIK_ALERT_WEBHOOK_URL`을 조립 루트가 주입한다. 작업 완료 보고용 `DISCORD_WEBHOOK_URL`은 읽지 않는다. `ZZIK_ALERTS=0`이면 전용 URL이 있어도 강제로 전송을 끈다. 없으면 전송 없이 건수만 로그에 남긴다. 웹훅 기본 이름 `피짱`을 쓰며 payload의 `username`은 생략한다. 본문은 제공자·한도 라벨·이전→현재 레벨·사용률/기간 경과 예상·리셋 남은 시간·대시보드 링크다. 멘션은 차단한다. Discord 한 메시지 길이를 넘으면 나머지 건수와 대시보드 확인 안내로 줄인다.
- HTTP timeout은 5초, redirect는 따라가지 않고 재시도하지 않는다. 예외·비정상 HTTP·로깅 실패가 수집 주기를 실패시키지 않는다. 웹훅 URL·응답/오류 원문은 로그에 넣지 않는다.
- **중복 방지를 우선한 한 번의 전송 시도**다. 전송 전 체크포인트하므로 성공 직후 재시작해도 반복하지 않는다. 반대로 체크포인트 직후 중단되거나 전송에 실패하면 해당 이벤트는 재전송하지 않는다. Discord 전달 보장/영속 outbox는 이번 범위 밖이다. `alerts=failed`는 PM2 표준 출력에 남는다. 기본 파일은 `~/.pm2/logs/zzik-usage-collector-out.log`이며 `pm2 logs zzik-usage-collector --out --lines 20 --nostream`으로 확인한다. 기존 `~/Library/Logs/zzik/usage-collector.log`의 제공자 로그와 구분한다.
- `diffAlerts`와 `nextAlertState`는 한 try 경계에서 계산한다. 어느 쪽이든 실패하면 이벤트 없음·기존 기준선 유지로 처리하며 정상 수집/저장을 계속한다.
- dry-run은 DB·상태·운영 로그 파일을 쓰거나 웹훅을 호출하지 않는다. 표준 출력에 값·라벨·리셋 시각을 가린 이벤트 미리보기만 남긴다.

## 검증

기존 실데이터 기반 6제공자 픽스처와 카드/요약 parity, 진입·해제·악화·리셋·첫 기준선·재시작·플래핑, 저장/수집/전송 실패, 웹훅 미설정, 한 주기 일괄 전송, 실제 5초 abort 및 dry-run을 가짜 포트로 검증한다. 테스트에서 실제 웹훅·agy·운영 수집기는 실행하지 않는다.

## 추가 지출 이벤트 분리

Claude extra_usage는 유료 지출 예산이므로 구독 한도 caution/danger/리셋 비교에서 제외한다. 별도 `spendLimitReached` boolean을 상태 파일에 보존하고, 성공 관측에서 `spend_limit_reached`가 false→true 또는 true→false로 바뀐 경우만 “추가 지출 한도 도달/해제” 이벤트를 같은 주기 메시지에 합친다. 금액·통화·사용률은 이 이벤트에 넣지 않는다. 첫 관측/기존 상태 이행은 기준선만 만들며, null·필드 누락·가림은 이전 boolean을 유지한다. 금융 플래그 전이는 일반 창의 30분 쿨다운에 묶지 않는다. 기존 generic extra_usage 체크포인트는 제거하고 정상 해제로 보고하지 않는다.
