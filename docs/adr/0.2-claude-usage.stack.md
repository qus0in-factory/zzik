# 부록 A — 스택 추가: TanStack Query, ky, Hono, Zustand

## A1. 결정 요약

| 패키지 | 쓰는 곳 | 쓰지 않는 곳 | 맡는 일 |
|---|---|---|---|
| Hono | `worker/ui`, `worker/index.ts`(조립) | `worker/app`, `worker/domain`, `worker/infra` | 라우팅, 미들웨어 순서, 응답 매핑 |
| ky | `src/infra`, `src/main.tsx`(인스턴스 생성) | 프론트의 다른 레이어, Worker, 수집기 | 프론트의 HTTP 호출 |
| TanStack Query | `src/app`, `src/main.tsx`(QueryClient 생성) | `src/ui`, `src/domain`, `src/infra` | 서버 상태: 주기 조회, 가시성 정지, 중복 병합, 재시도 |
| Zustand | `src/app` | `src/ui`, `src/domain`, `src/infra` | 클라이언트 상태만 |

- 버전은 설치 시점의 최신 안정판으로 고정한다. 아래 옵션 이름은 Query v5 기준으로 적었으니 설치한 버전의 문서와 대조한다.
- domain은 세 루트 모두 외부 패키지 0개를 유지한다. app은 Worker에서는 프레임워크 무관, 프론트에서는 React·Query·Zustand까지만 허용한다.

## A2. Hono (Worker ui)

- `worker/ui/api.ts`가 `createApi(deps)`로 Hono 앱을 만든다. 본문 D11의 `router.ts`와 `respond.ts`를 대체한다. `worker/ui/usage/usage-route.ts`는 핸들러만 남는다.
- `deps`는 app 유스케이스(`authorize`, `getUsage`)에 포트를 묶은 것이고 `worker/index.ts`가 env로부터 만든다. app과 domain은 Hono 타입(`Context` 등)을 받지 않는다. 핸들러가 헤더 문자열을 꺼내 넘기고 결과 유니온을 받아 응답으로 바꾼다.
- 본문 D8의 판정 순서를 미들웨어 순서로 고정한다.
  1. `app.use('/api/*')` 설정 확인 → 500 `misconfigured`
  2. `app.use('/api/*')` 인증 → 401 `unauthorized`, 503 `jwks_unavailable`
  3. `app.get('/api/usage')` → 200, 502, 503
  4. `app.all('/api/usage')` → 405 (Hono는 메서드 불일치를 기본 404로 처리하므로 직접 둔다)
  5. `app.all('/api/*')` → 404
  6. 그 밖의 경로 → `c.env.ASSETS.fetch(c.req.raw)`
- 공통 헤더(`no-store`, `nosniff`)는 `/api/*` 미들웨어 하나에서 붙인다.
- JWT 검증은 Hono의 JWT 미들웨어를 쓰지 않고 본문 D7의 `jose` 구현(infra)을 그대로 쓴다. 검증 로직이 ui 프레임워크에 묶이지 않게 하기 위해서다.

## A3. ky

- 프론트: `src/main.tsx`가 `ky.create({ retry: 0, throwHttpErrors: false, redirect: 'manual', timeout: 10_000 })` 인스턴스를 만들어 `createHttpUsageGateway(http)`에 넣는다. 게이트웨이는 본문 D9-3의 매핑(200, `opaqueredirect`, 401/5xx, 예외)을 그대로 한다.
  - ky의 재시도는 끈다. 재시도 정책은 Query 한 곳에만 둔다(A4).
  - `throwHttpErrors: false`로 상태 코드를 직접 읽어 결과 유니온으로 바꾼다. infra가 예외를 밖으로 내지 않는다는 규칙을 유지한다.
  - 확인 필요: `redirect: 'manual'`에서 ky가 `opaqueredirect` 응답(status 0)을 그대로 돌려주는지. 게이트웨이 테스트로 고정하고, 안 되면 이 호출만 `fetch`를 직접 쓴다.
- 수집기: ky를 쓰지 않고 Node 24의 `fetch`를 유지한다.
  - 부록 B 이후 수집기의 HTTP 호출은 usage GET 하나뿐이다(KV 쓰기는 wrangler 실행). 재시도는 실행 사이의 게이트(본문 D5)가 맡고 실행 안에서는 재시도하면 안 되므로 ky의 재시도·훅이 쓸 데가 없다. 타임아웃은 `AbortSignal.timeout`으로 충분하다.
  - Claude OAuth 토큰을 읽는 프로세스가 import하는 외부 코드를 0개로 유지한다. 부록 B로 수집기가 레포에서 실행되어 `node_modules`가 닿는 위치에 있게 되지만 이 판단은 바뀌지 않는다.
- Worker: 바깥으로 나가는 HTTP는 `jose`의 JWKS 조회뿐이라 ky를 넣지 않는다.

## A4. TanStack Query (프론트 app)

파일별 처리:

| 파일 | 처리 |
|---|---|
| `src/app/usage/usage-poller.ts` | 삭제. 주기, 가시성 정지, 중복 병합을 Query가 맡는다 |
| `src/app/usage/usage-query.ts` | 추가. `usageQueryKey = ['usage', 'claude']`, `usageQueryOptions(gateway)`, `shouldRetryUsage`, `UsageLoadError` |
| `src/app/usage/load-usage.ts` | 축소. 게이트웨이 호출부는 `usage-query.ts`로 가고, "성공 결과 + now → 뷰(보고서, 수집 판정)" 변환만 남는다 |
| `src/app/usage/useUsage.ts` | 축소. `useQuery` + 30초 now 틱 + 4상태 매핑. 반환 형태(`{ state, refresh }`)는 그대로라 ui는 바뀌지 않는다 |
| `src/app/query-client.ts` | 추가. `createAppQueryClient()` (기본 옵션과 재시도 정책) |
| `src/app/usage/UsageGatewayContext.tsx` | 유지. 게이트웨이, 시계, 스케줄러(now 틱용)를 전달한다. `visibility`는 뺀다 |
| `src/domain/usage/gateway.ts` | `UsageVisibility` 포트 삭제. `UsageGateway`, `UsageClock`, `UsageScheduler`는 유지 |
| `src/infra/usage/browser-runtime.ts` | `createBrowserVisibility` 삭제 |
| `src/main.tsx` | `QueryClientProvider`로 감싼다. QueryClient는 여기서 한 번 만든다 |

동작 대응:

| 0.2.1 동작 | Query 설정 |
|---|---|
| 60초 주기 호출 | `refetchInterval`. 오류가 `session_expired`면 `false`를 돌려 폴링을 멈춘다(재로그인 전에는 의미가 없다) |
| 탭이 숨겨지면 정지 | `refetchIntervalInBackground: false`(기본값) |
| 탭이 다시 보이면 즉시 호출 | `refetchOnWindowFocus: true`, `staleTime: 30_000`(탭을 빠르게 오갈 때의 연속 호출 방지) |
| 진행 중 호출에 합치기 | 같은 queryKey의 자동 병합. 수동 새로고침은 `refetch({ cancelRefetch: false })`로 호출한다. 기본값(`true`)은 진행 중 요청을 취소하고 새로 보내므로 합쳐지지 않는다 |
| 실패해도 마지막 보고서 유지 | 재조회 실패 시 Query가 이전 `data`를 유지한다 |

- queryFn은 게이트웨이 포트만 호출한다(`gateway.fetchUsage()`). `fetch`나 ky를 직접 부르지 않는다.
- 결과 유니온과 예외의 경계: 게이트웨이는 계속 결과 유니온을 돌려준다. queryFn이 `ok: false`를 `UsageLoadError`(reason, message 보유)로 던진다. Query의 오류·재시도 모델이 예외 기반이기 때문이며, 예외를 쓰는 곳은 이 어댑터 한 곳뿐이다.
- 캐시에는 게이트웨이 성공 결과(raw, 수집 정보)를 넣고, 뷰는 훅에서 `now`와 함께 `useMemo`로 만든다. 30초 틱마다 리셋 문구와 stale 판정이 다시 계산된다(0.2.1은 조회 시점에만 계산했다).
- 4상태 매핑: 데이터도 오류도 없음 → `loading`. 데이터 있고 오류 없고 수집 판정 정상 → `ready`. 데이터 있고 오류 또는 수집 판정 비정상 → `stale`. 데이터 없고 오류 → `error`.
- 재시도: `shouldRetryUsage(count, error)`는 `network_error`만 2회까지 허용한다. `session_expired`(재로그인 필요)와 `api_error`(401, 5xx, 503)는 재시도하지 않고 다음 주기를 기다린다.
- 429: 브라우저는 Worker의 KV 읽기만 호출하므로 upstream 429를 직접 보지 않는다. 그것은 수집기의 일이고(본문 D5), 화면에는 데이터 안의 `collection.status: 'rate_limited'`로 온다. Query의 재시도 대상이 아니다. Worker 자신이 429를 주면 `api_error`로 보고 다음 주기를 기다린다.
- 재시도 정책은 훅의 옵션이 아니라 `createAppQueryClient()`의 기본 옵션에 둔다. 훅에 두면 테스트 클라이언트의 `retry: false`가 덮이지 않는다.

## A5. Zustand (프론트 app)

- 스토어는 `src/app/usage/usage-ui-store.ts` 하나다. ui는 스토어를 직접 import하지 않고 app이 내보내는 훅(`useRawJsonOpen`, `useFixtureChoice`)으로 쓴다.
- 넣는 것:
  - (제거됨, #24) `rawJsonOpen`: Raw JSON 펼침 여부. 조회 상태가 바뀌어 대시보드가 다시 마운트돼도 유지된다.
  - `fixtureName`(DEV 전용): 픽스처 선택. 초기값은 기존 `?fixture=` 쿼리에서 읽는다. 조립 루트가 fixture 게이트웨이에 `() => store.getState().fixtureName` getter를 넘기고, 값이 바뀌면 `queryClient.invalidateQueries({ queryKey: usageQueryKey })`를 호출한다. infra는 스토어를 import하지 않는다.
- 넣지 않는 것: 보고서, 봉투, 수집 판정, 로딩·오류 상태, 마지막 성공 시각. 서버에서 온 값과 거기서 파생된 값은 Query 캐시와 훅의 파생 계산에만 둔다.
- persist 미들웨어는 쓰지 않는다.
- 지금 대상은 값 두 개다. 스토어를 미리 넓히지 않고, 클라이언트 상태가 생길 때 이 스토어에 더한다.

## A8. 채택하지 않은 것

| 대안 | 이유 |
|---|---|
| 수집기에 ky | A3. 의존성 없는 설치와 실행 내 무재시도 원칙에 맞지 않는다 |
| 재시도를 ky에 맡기기 | 재시도가 두 층(ky, Query)에 생기면 호출 수가 곱해진다. Query 한 곳에 둔다 |
| queryFn이 결과 유니온을 데이터로 반환(예외 없음) | 실패가 성공 데이터로 캐시되어 이전 보고서가 덮이고, Query의 재시도와 오류 상태를 쓸 수 없다 |
| ui에서 `useQuery` 직접 호출 | ui가 서버 상태 라이브러리에 묶이고 0.2.1의 ui 테스트(프롭 기반)를 다시 써야 한다 |
| Query 캐시에 뷰 모델 저장 | `now`에 따라 달라지는 값이 캐시에 굳는다. 30초 틱 재계산이 불가능해진다 |
| Zustand에 보고서나 조회 상태 보관 | 서버 상태의 출처가 둘이 된다 |
| Hono의 JWT/Access 미들웨어 | 검증 로직이 ui 프레임워크에 들어가고 본문 D7의 실패 구분(401과 503)을 직접 다루기 어렵다 |
| Worker app을 Hono 컨텍스트 기반으로 작성 | app이 프레임워크에 묶여 Node 테스트에서 포트 주입만으로 돌릴 수 없게 된다 |

## A9. 결과

- 0.2.1의 직접 만든 폴러(약 90줄)와 그 테스트, 가시성 포트가 사라지고 같은 동작이 Query 설정 몇 줄로 옮겨진다. 그 동작의 보증은 `useUsage` 테스트 몇 개와 라이브러리에 넘어간다.
- `useUsage`의 반환 형태와 ui 컴포넌트는 그대로다. 0.2.1의 ui 테스트는 고치지 않는다.
- 리셋 문구와 stale 판정이 조회 시점이 아니라 30초마다 갱신된다.
- 예외를 쓰는 지점이 하나 생긴다(queryFn 어댑터). 그 밖의 레이어는 결과 유니온 규칙을 유지한다.
- 프론트 번들에 의존성 세 개, Worker 번들에 하나가 더해진다. 값 두 개에 Zustand를 쓰는 것은 지금 기준으로는 과하고, 이후의 클라이언트 상태를 한 곳에 모으는 자리로 둔다.
- 구현 순서: 본문 구간 A(Worker)에서 Hono를, 구간 B(프론트)에서 ky → Query → Zustand 순으로 넣는다. Query 전환은 본문 D9의 계약 확장과 같은 커밋 묶음에서 한다(`useUsage`를 두 번 고치지 않게).

# 부록 B — 운영 제약 변경: SSH 전용, 무인 실행

## B1. 바뀐 제약

- 사용자는 이 Mac에 원격 SSH로만 접근한다. Mac 화면에서 하는 승인(Keychain "항상 허용", 백그라운드 항목 알림)과 대시보드에서의 토큰 발급을 전제할 수 없다.
- 수집은 사람 손 없이 계속 돌아야 한다. 이 Mac에는 PM2가 이미 설치되어 있다(biseo를 돌리던 것).
- biseo는 정지했고 앞으로 쓰지 않는다. 같은 엔드포인트를 호출하는 다른 프로세스는 이제 없다.
- 확인된 사실: `~/.claude/.credentials.json`은 Claude Code가 갱신하고 있다(2026-11-11 19:35 갱신 확인). KV namespace가 만들어져 있다(id `5fe6ac40c73c4d05ac2fab052c2100e6`). 이 Mac의 wrangler는 로그인되어 있다.

| 항목 | 본문 v2 | 부록 B |
|---|---|---|

| 수동 단계 | 대시보드와 Mac 화면 작업 포함 | SSH 명령만 |

삭제되는 것: `collector/install.sh`, `uninstall.sh`, `set-token.sh`, `launchd.plist.template`, `infra/usage/keychain.mjs`, `kv-token-file.mjs`, REST용 `kv-writer.mjs`, 봉투의 `kvTokenExpiresAt`, 화면의 "API 토큰 만료" 판정과 14일 전 경고, `--no-keychain` 플래그, 본문 전제 2·8·9·10, V16.

## B3. D2 수정 — 수집기 실행 (PM2)

- 실행 형태: PM2 앱 `zzik-usage-collector`가 `collector/main.mjs --loop`를 상주시킨다. 프로세스 안에서 5분마다 `run-once`를 부른다.
  - `cron_restart` + 실행마다 종료 방식은 쓰지 않는다. PM2는 상주 프로세스 관리자라 `online` 상태와 재시작 횟수가 곧 수집기의 건강 지표가 되고, 멈춘 앱을 cron이 다시 띄우는 동작은 PM2 버전에 따라 달랐던 이력이 있다.
  - 루프는 이전 실행이 끝난 뒤에 다음 실행을 예약한다(겹침 없음). 한 번의 실행이 실패해도 루프는 계속된다. 게이트와 마지막 봉투는 계속 상태 파일에 두므로 PM2가 프로세스를 재시작해도 백오프가 이어진다.
  - 루프의 타이머는 스케줄러 포트로 주입한다(테스트용).
- 등록: `collector/ecosystem.config.cjs`.

```js
module.exports = {
  apps: [{
    name: 'zzik-usage-collector',
    script: 'collector/main.mjs',
    args: '--loop',
    cwd: '/Users/young-mini/Workspace/zzik',
    autorestart: true,
    restart_delay: 30000,
    max_memory_restart: '150M',
    time: true,
    env: {
      ZZIK_KV_NAMESPACE_ID: '5fe6ac40c73c4d05ac2fab052c2100e6',
      ZZIK_KV_KEY: 'usage:claude',
      ZZIK_INTERVAL_SEC: '300',
      CLOUDFLARE_ACCOUNT_ID: 'c89ea66c04742e4f6f1feb8dd8e5b775',
      WRANGLER_SEND_METRICS: 'false',
    },
  }],
}
```

- 실행 위치는 레포의 main 체크아웃이다. wrangler를 레포의 devDependency에서 쓰기 때문이다. 수집기 갱신은 `git pull` → (의존성이 바뀌었으면 `pnpm install`) → `pm2 restart zzik-usage-collector`다. main 체크아웃은 항상 main 브랜치에 둔다(작업은 worktree에서 한다는 기존 규칙).
- 로컬 파일: `~/Library/Application Support/zzik/usage-state.json`(0600, 디렉터리 0700)과 KV에 올릴 봉투의 임시 파일(같은 디렉터리, 0600)만 남는다. 설정은 ecosystem의 env로 받는다. 로그는 PM2가 관리한다(`~/.pm2/logs/zzik-usage-collector-*.log`). 한 실행에 한 줄이라는 규칙과 토큰을 적지 않는 규칙은 그대로다.
- CLI: `--loop`(PM2용), `--once`, `--dry-run`, `--credentials-file <path>`(`--dry-run`과 함께일 때만).
- 부팅 후 복구는 PM2 startup에 얹는다(`pm2 save`). startup이 설정되어 있지 않으면 `pm2 startup`이 출력하는 sudo 명령을 SSH에서 한 번 실행한다.

## B4. D3 수정 — 자격 증명

| 비밀 | 위치 | 용도 | 비고 |
|---|---|---|---|
| Claude OAuth access token | `~/.claude/.credentials.json` (Claude Code 소유) | usage 호출 | 읽기만 한다. Keychain은 보지 않는다 |
| wrangler OAuth 로그인 | wrangler 설정 디렉터리(기존) | KV 쓰기 | 새로 만드는 비밀이 없다 |
| Worker 쪽 비밀 | 없음 | | |

Claude 토큰:

- 파일 하나만 읽는다. `claudeAiOauth.accessToken`, `claudeAiOauth.expiresAt`. 파일이 없거나 읽을 수 없거나 형식이 다르면 `no_credentials`다.
- 갱신하지 않는다는 결정, `token_expired`와 `auth_required` 처리, 공백 추정식은 본문 D3 그대로다. `credential-choice.mjs`는 "둘 중 선택"이 사라져 만료 판정만 남는다.
- 화면 잠금과 무관해진다. 본문의 U8(잠금 해제)은 없어진다.

KV 쓰기 (wrangler 어댑터):

- `collector/infra/usage/wrangler-kv-writer.mjs`가 `KvWriter` 포트를 구현한다. 봉투를 임시 파일에 쓰고 다음을 실행한다.

```
<node> node_modules/wrangler/bin/wrangler.js kv key put usage:claude \
  --path <임시 파일> --namespace-id 5fe6ac40c73c4d05ac2fab052c2100e6 --remote
```

  - 값을 인자가 아니라 `--path`로 넘긴다(길이와 이스케이프 문제 회피).
  - wrangler를 `process.execPath`로 직접 실행한다. PM2 환경의 PATH에 node가 없어도 동작한다.
  - `execFile`(셸 없음), 타임아웃 60초. 종료 코드 0이 아니면 KV 쓰기 실패로 보고 stderr의 첫 줄만 로그에 남긴다. 인증 오류로 보이면 `kv_auth_failed`로 적는다.
  - 확인 필요: 레포의 wrangler 4.159에서 위 플래그 조합과 wrangler 실행 파일 경로가 맞는지(V6에서 실제 1회 실행).
- 수집기 코드가 import하는 외부 패키지는 여전히 0개다. wrangler는 외부 프로세스로만 쓴다(A7 규칙 유지).
- 본문 v2가 이 방식을 기각했던 이유는 그대로 남는 대가다. 제약 때문에 받아들인다.
  - 권한: wrangler OAuth는 KV뿐 아니라 Worker 배포까지 할 수 있다. 그 자격 증명은 이미 이 Mac의 디스크에 있었고 새로 놓이는 비밀은 없다. 달라지는 것은 그것을 5분마다 무인으로 쓰는 프로세스가 생긴다는 점이다.
  - 세션 의존: wrangler가 access token을 스스로 갱신하는 동안은 무인으로 돈다. refresh가 실패하면 KV 쓰기가 멈추고 화면에는 "수집 중단"으로 보인다. 복구는 재로그인이다(B7의 U5).
  - 경합: 수집기의 wrangler와 사용자의 `wrangler deploy`가 같은 순간에 토큰을 갱신하면 한쪽이 실패할 수 있다. 수집기 쪽은 다음 주기에 복구된다.
  - 비용: 5분마다 Node 프로세스 하나가 1~2초 뜬다.
  - CLI 의존: wrangler 판올림으로 플래그가 바뀌면 어댑터를 고쳐야 한다. 버전은 `package.json`에 고정되어 있다.
- 리뷰 H1의 쟁점(계정 전체 KV 권한의 상시 토큰, Keychain ACL, 교체 절차)은 전용 토큰 자체가 없어져 해당 사항이 없어진다. 대신 위의 "더 넓은 OAuth를 무인으로 사용"이 그 자리를 차지한다.
- 봉투에서 `kvTokenExpiresAt`을 뺀다. 본문 D4의 "API 토큰 만료" 줄과 14일 전 경고를 뺀다. 나머지 판정 표는 그대로다.

테스트 추가분:

## B6. biseo 결과 재사용 여부

판단: 미채택. biseo 운영이 종료되어 재사용할 결과가 없다.

- zzik 수집기가 Anthropic usage 엔드포인트를 직접 호출한다. 주기 5분, 429 백오프는 본문 D5 그대로다.
- biseo가 멈췄으므로 같은 토큰으로 이 엔드포인트를 호출하는 프로세스는 zzik 수집기 하나다. 호출이 겹쳐 429가 늘 것이라는 본문 전제 9의 우려는 없어진다. 하루 호출 수는 biseo 시절의 1,440회에서 288회로 줄어든다.
- 참고로 biseo가 살아 있었더라도 그 스냅샷은 가공된 값이라(값이 `null`인 키와 항목의 추가 필드가 빠짐) "응답의 모든 항목"과 "raw JSON 그대로"를 채울 수 없었다.
- biseo의 스냅샷 파일이나 로컬 API에 의존하는 코드는 두지 않는다. `UsageSource` 포트의 구현은 `usage-client.mjs` 하나다.

## B7. 사용자 수동 단계 (본문 표 대체, 전부 SSH)

에이전트가 SSH 세션에서 대신 실행할 수 있는 명령들이다. 사용자 승인이 필요한 것은 U1과 U3뿐이다.

| # | 시점 | 작업 |
|---|---|---|
| U1 | 수집기 코드가 main에 들어간 뒤 | `pm2 start collector/ecosystem.config.cjs && pm2 save` |
| U2 | U1 직후 | `pm2 describe zzik-usage-collector`와 `pm2 logs zzik-usage-collector --lines 20`으로 `online`과 첫 수집 줄을 확인 |
| U3 | (PM2 startup이 없을 때만) | `pm2 startup`이 출력하는 sudo 명령을 실행 |
| U4 | 화면에 "인증 필요"가 뜰 때 | 이 Mac에서 Claude Code를 한 번 실행한다(SSH 세션에서 `claude`). 토큰을 갱신하는 유일한 수단이다 |
| U5 | 로그에 `kv_auth_failed`가 반복될 때 | `pnpm exec wrangler whoami`로 확인하고, 로그아웃 상태면 `pnpm exec wrangler login`을 다시 한다. 로그인 콜백이 이 Mac의 localhost로 오므로 SSH 접속에 포트 포워딩(`-L 8976:localhost:8976`)을 걸고 출력된 URL을 원격 기기의 브라우저에서 연다 |
| U6 | 수집기 코드가 바뀐 뒤 | `git pull` → `pm2 restart zzik-usage-collector` |
| U7 | 제거할 때 | `pm2 delete zzik-usage-collector && pm2 save`, 상태 디렉터리 삭제 |

- 본문의 U1(Access Worker destination 확인)은 대시보드 작업이라 SSH로 할 수 없고 wrangler OAuth에는 Access 권한이 없다. 0.1 D3의 "백스톱 불가 시"에 따라 미확인 편차로 기록하고 진행한다. 데이터 쪽은 본문 D7의 JWT 검증이 막는다. 대시보드에 접근할 수 있게 되면 그때 확인한다.
- U5의 포트 번호는 wrangler가 로그인 때 출력하는 값을 따른다.
- 배포 후 화면 확인(V11~V13)은 원격 기기의 브라우저로 zzik에 접속해서 한다. 이것은 설치 단계가 아니라 제품을 쓰는 일이다.

## B8. 검증 수정

- V6에 추가: `--once`를 한 번 실제로 돌려 wrangler 어댑터가 KV에 쓰는지 확인한다(`pnpm exec wrangler kv key get usage:claude --namespace-id 5fe6ac40c73c4d05ac2fab052c2100e6 --remote`로 `runAt` 대조). `--no-keychain`이 들어간 항목은 `--credentials-file`만으로 바꾼다.
- V8 대체: `pm2 describe zzik-usage-collector`가 `online`이고 재시작 횟수가 늘지 않는다. 로그에 5분 간격으로 줄이 늘어난다. 로그와 `usage-state.json`에 토큰 문자열이 없다. 상태 파일 권한이 0600, 디렉터리가 0700이다. `pm2 restart` 직후에도 게이트(`nextAllowedAt`)가 유지된다.
- V13 대체: `pm2 stop zzik-usage-collector` 후 15분 넘게 기다리면 "수집 중단" 배지가 나오고, `pm2 start` 후 다음 실행 뒤 "정상"으로 돌아온다.
- V14 수정: API 토큰 권한 기록과 KV namespace 민감 값 확인 항목을 뺀다. `wrangler whoami`의 계정이 `c89ea66c04742e4f6f1feb8dd8e5b775`인지와, Worker destination이 미확인 편차로 기록되어 있는지를 본다.
- V15는 그대로다(zzik 로그의 `status` 분포). `rate_limited`가 잦으면 주기를 늘린다. biseo와의 비교 항목은 없다.
- V16(토큰 교체 리허설) 삭제.

## B9. 결과

- 사람이 Mac 화면이나 대시보드에서 해야 하는 설치 단계가 없어진다. 등록, 점검, 복구가 모두 SSH 명령이다.
- 새로 만드는 비밀이 없다. 토큰 파일, 만료일 관리, 교체 절차가 사라진다.
- 수집기가 wrangler OAuth 세션, 레포 main 체크아웃, 그 `node_modules`에 의존하게 된다. 셋 중 하나가 깨지면 수집이 멈추고 화면에는 "수집 중단"으로만 보인다(원인은 PM2 로그에서 본다).
- 배포 권한까지 가진 자격 증명을 무인 프로세스가 주기적으로 쓴다. 본문 v2가 피하려던 지점이며 제약 때문에 수용한다.
- 상주 프로세스가 하나 생긴다. "실행마다 종료"라는 본문 D2의 성질은 없어지고 PM2가 관리한다.
- usage 엔드포인트를 호출하는 것은 zzik 수집기뿐이다. biseo와의 호출 중복과 그에 따른 429 우려는 없어졌다.
- Access의 Worker destination은 미확인 상태로 남는다.
