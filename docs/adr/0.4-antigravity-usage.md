# ADR 0.4: Antigravity 사용량

상태: 브랜치 구현 완료, **운영 검증 대기**. 사용자 승인된 Antigravity UA로 G2a dry-run 재시도 1회가 성공했다([기록](../research/0.4-g2a-antigravity.md)). 이 작업에서는 배포·KV 쓰기·PM2 재시작을 하지 않는다.

## 배경

0.3의 제공자별 자격 증명·usage 포트·KV 키·상태 파일·프론트 정규화기를 재사용한다. 새 패키지·Access 변경·사용자 설정 변경 없음. 설계 정본은 /tmp/fable-antigravity.md, 조사 근거는 /tmp/gemini-antigravity-probe.md다. ~/Factory/biseo의 agy 파서·설정은 읽기만 했다.

probe의 마스킹 성공 형상은 groups 배열 → 그룹 displayName/description/buckets 배열 → 버킷 bucketId/displayName/window/resetTime/description/remainingFraction이다. 최상위 description도 있다. 초기 UA 없는 dry-run은 인증 거부였고, 사용자 승인 UA 추가 후 기본 호스트에서 1회 재시도하여 HTTP 200을 확인했다.

미확인 전제: agy/IDE 갱신이 파일에 반영되는지,  IDE와 CLI가 같은 파일을 사용하는지.

## D2. 읽기 전용 자격 증명

기본 경로 ~/.gemini/antigravity-cli/antigravity-oauth-token. token.access_token, token.expiry만 추출한다. 반환은 source=antigravity, token, expiresAt=number 또는 null, accountId=null. refresh_token/id_token_email/auth_method/expires_in은 결과에 없다.

rfc3339-ms.mjs 순수 함수가 소수 초를 3자리로 잘라 Date.parse한다. 불명확한 만료는 null로 서버 판정. 파일/JSON/access_token이 없으면 null. 파싱 실패는 200ms 뒤 1회 재시도. 0600보다 넓은 권한에는 값 없는 경고. 파일 쓰기 없음. 기존 60초 마진·token_expired 상태 공유.

수집기는 토큰을 갱신하지 않는다. 갱신 소유자는 agy/Antigravity이며 제3자 OAuth client secret을 복제하지 않는다.

## D3. 조립·예산

main 조립 루트가 제공자별 credentials/usage/state/KV 포트를 주입한다. provider-bundles 순수 배선 재사용, --provider antigravity 허용. Codex 계정 헤더는 Antigravity에 전달하지 않는다.

세 제공자를 순차 실행하면 대략 3×(10초+wrangler)로 240초 예산 안이다. 예산 소진 시 세 번째 건너뜀 테스트. 300초마다 세 키에 쓰면 864회/일(KV Free 1,000회의 약 86%). 네 번째는 주기 재설계 없이 추가하지 않는다.

## D4. 요청·분류·호스트 허용 목록

POST https://cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary.
허용 host는 기본값과 daily-cloudcode-pa.googleapis.com뿐이다. 다른 env 값은 호출 전 종료 78.
본문 project는 env 또는 default-cli-project. 헤더는 Authorization Bearer/Content-Type application/json/Accept application/json과 User-Agent: Antigravity/1.0. UA 값은 ANTIGRAVITY_USER_AGENT 상수로 고정한다. redirect manual, 10초 타임아웃.

**ADR 0.3 D4 예외(사용자 승인, 2026-11-13):** Antigravity 계열 UA 사용을 사용자가 승인했다. gemini 요청 대조 보고(/tmp/gemini-antigravity-denied.md)에서 UA 누락을 원인으로 확인했으며 승인된 UA만 추가해 재시도 1회로 성공했다. probe와 같은 Antigravity/1.0을 사용한다(biseo의 antigravity/hub 계열과 동일 제품 계열). 다른 제공자의 헤더 정책·project·호스트·갱신 정책은 바꾸지 않는다.

200 JSON 객체는 성공 본문을 기존 봉투로 전달, 비JSON 200은 upstream_error.
401/JSON 403은 auth_required(run-once에서 expiresAt으로 auth_rejected/auth_required 분기).
비JSON 403·3xx·기타 4xx/5xx는 upstream_error, 429는 rate_limited 및 기존 Retry-After 규칙.
timeout/abort는 upstream_error, 연결 실패는 network_error.
Google error.status는 안전한 enum만 diag에 기록한다. error.message·본문·토큰·계정은 진단에 남기지 않는다.

## D5. 봉투·가림·게이트

기존 schema 1·rawRedacted·runAt 계약 공유. 가림 목록 기본은 빈 배열이나 실제 성공 응답 쓰기 전에 description의 식별자 여부(U2)를 확인해야 한다. @ 포함 여부는 메모리에서 yes/no만 출력. 포함되면 최상위·그룹·버킷 description 경로를 먼저 가린다.

1. G2a: 실제 자격 증명 dry-run으로 status·키 경로·sha256만 기록. 사용자 승인 UA를 넣은 재시도 1회 HTTP 200/status=ok로 통과.
2. U2: 이번 성공 응답의 최상위·그룹·버킷 description @ 포함 여부=no. 실제 설명은 출력하지 않았으며 테스트 픽스처의 설명·표시명·원래 bucketId는 모두 마스킹했다. 임의 개인 문자열이 전혀 없다는 일반적 보증은 아니므로 향후 응답 형상 변경 시 재확인한다.
3. 별도 승인 후 KV 쓰기 활성화 → G2b live-shape 및 마스킹 live fixture로 라벨·주기 확정.
4. 프론트 섹션 main 반영은 G2b 이후.
5. G1: agy 파일 갱신과 수집기 token_refreshed 로그 자동 해제 관측.
6. G1 실패 시 F1: ZZIK_PROVIDERS=claude,codex.

## D6. 프론트 버킷 정규화

antigravity-buckets.ts가 API 형상을 스캔하고 antigravity-labels.ts가 라벨/주기를, antigravity-view.ts가 기존 UsageReport를 만든다. 아래 표는 G2b 전까지 잠정이다.

| 규칙 | 결정 |
|---|---|
| 형상 | 최상위 객체/groups 배열 아니면 invalid_shape. 그룹 객체/buckets 배열 아니면 invalid_entry(groups[i]) |
| 카드 | 버킷 하나당 windows 한 장. metrics=[] |
| id | 유일한 비공백 bucketId, 중복/없음은 groups[i].buckets[j] 경로 |
| usedPercent | 유한한 0..1 remainingFraction이면 clamp((1-f)×100,0,100). 그 외 invalid_utilization 후 생략 |
| 표시 숫자 | domain 정밀도 유지. UI 소수 최대 1자리 포맷. Progress 실제 값 유지 |
| 주기 | 5h=18000초, weekly=604800초. 모르는 window는 null, 정규식 추정 없음 |
| 라벨 | 그룹 displayName(없으면 그룹 i+1) · 5시간 한도/주간 한도. 미지 window 한도 + unknown |
| resetsAt | 파싱 가능한 resetTime 문자열 보존, 아니면 null |
| elapsedPercent | 기존 함수에 버킷 주기와 now 직접 주입. Claude cycleSeconds(id) 사용 안 함 |
| 상태 | usageLevelOf/aggregateUsageLevel 및 기존 expired/resetText 규칙 |
| 정렬 | 그룹 순서 → 주기 오름차순(미지 뒤) → id |
| others | 최상위 groups 제외 키만 보존. 그룹·버킷 description은 중복 표시하지 않음 |
| 가림 | app이 rawRedacted를 기존 visibleUsageReport로 전달. 기타 UI는 #28대로 숨김 |

## D7. Worker·화면

shared 목록/KV 키 추가로 /api/usage/antigravity가 열리며 인증은 동일하다. 정상 200·provider 불일치 502·대문자 Antigravity 경로 404 테스트.

등록부 순서대로 세 번째 섹션/요약 칩이 된다. title/clientName은 Antigravity, sectionId는 usage-antigravity, ariaLabel은 Antigravity 사용량. 안내는 이 Mac에서 Antigravity(agy)를 실행하면 갱신된다는 문구. 탭이나 토큰 수명 문구는 추가하지 않는다.

DEV normal/limited/unknown-keys 시나리오와 resetTime 기준 시각 상대 보정. 320px의 세 칩·섹션·긴 라벨 확인.

## D8. 디렉터리·테스트·검증

tests/는 소스 경로를 미러링. RFC3339, 자격 증명 재시도/만료/비밀 배제, POST·host·오류 enum·타임아웃, 제공자 계약 일치, 세 제공자 순서/각자 KV/예산, 버킷 형상/중복 id/fraction 범위/미지 주기/정렬/상태, Worker/snapshot/load/안내/DEV 날짜 보정/화면 세 섹션·칩 테스트.

normal/limited/unknown-keys 및 auth.* 픽스처는 probe 마스킹 형상 위에 합성 값을 넣었다. 실제 성공 응답 추출 live fixture와 구분한다. 승인 UA 재시도 성공 응답에서 메모리 마스킹한 antigravity-usage.live.json을 추가했다. 구조·숫자·window·resetTime을 유지하고 원래 bucketId는 합성 id로, 표시명·description은 마스킹하여 저장했다. 고정 now에서 버킷 2개·사용률 0/99.4456%·경과율을 검증한다. live-shape 스크립트는 antigravity와 bucketId/displayName/window 라벨을 지원하며 description은 길이만 보여 준다.

필수 검증: pnpm test/build/typecheck/typecheck:collector, 가짜 만료/없는 자격 증명 dry-run, host 허용 목록 밖 거부, 320px 화면.

## D9. 후속 운영·위험·대안

별도 승인 뒤 배포 → ecosystem 활성 제공자 갱신 → PM2 restart --update-env → 세 제공자 로그/상태/KV 키 → G2b 대조를 수행한다. 이번 작업에서는 실행하지 않는다.

토큰은 probe 기준 약 1시간 수명. agy 미사용 중 token_expired가 지속될 수 있다. 마지막 성공 값과 리셋 시각은 보존하며 stale 안내한다. 며칠 관측해 token_expired 비율이 50%를 넘으면 후속으로 추론 없이 agy 갱신을 유도하는 명령을 조사한다.

비공개 v1internal 구조 변경, IDE/CLI 파일 차이, 자유 텍스트 description, KV 예산은 남은 위험이다. 실제 앱과 API UI 값은 ±1 수집 주기 범위로 대조한다.

미채택/범위 밖: OAuth 직접 refresh·client secret, Keychain, retrieveUserQuota 세부 모델, CLI 추론 폴백, 승인되지 않은 UA, Gemini CLI oauth_creds.json, 탭 UI, /api/usage 별칭 제거, 네 번째 제공자 주기 변경.

## 변경 (2026-11-13): Gemini·Argon 추가 — UA 변경, 요청 본문, Argon 합성

근거: /tmp/gemini-agy-gemini-argon.md(실측). 요약 API는 User-Agent로 반환 그룹을 거른다 — `Antigravity/1.0`은 Claude·GPT 그룹만, `antigravity/hub/2.9.1`은 Gemini 그룹까지 돌려준다. 사용자가 Gemini와 Argon 둘 다 요청했으므로 기존 Antigravity UA 예외의 범위(같은 제품 계열 UA) 안에서 다음을 바꾼다. 다른 헤더·호스트·갱신 정책은 그대로다.

- **UA:** `ANTIGRAVITY_USER_AGENT = 'antigravity/hub/2.9.1'`(이전 `Antigravity/1.0`). 변경 사유는 위 필터링 동작. 요청 본문은 `{}`(조사대로)이며 `ZZIK_ANTIGRAVITY_PROJECT`는 더 이상 쓰지 않는다.
- **4개 창:** 같은 호출 1회로 Gemini(5h·weekly)와 Claude·GPT(5h·weekly)가 온다. 프론트 파서 변경 없음. 카드 제목은 알려진 그룹명만 줄인다 — `Gemini Models`→`Gemini`, `Claude and GPT models`→`Claude·GPT`(모르는 그룹은 응답 그대로).
- **Argon(방안 B):** API는 `Gemini 4 Argon` 그룹을 주지 않는다. 호출이 성공하면 수집기가 `agy -p /quota`(탭 구분 4열: 그룹·창 라벨·잔여%·UTC ISO)를 1회 실행해 Argon 행에서 `argon-weekly` 주간 버킷을 만들어 `groups`에 덧붙인다(`collector/domain/usage/agy-quota-cli.mjs` 순수 함수, 실행은 `infra/usage/agy-quota-cli-runner.mjs`). API에 이미 Argon이 있으면 합성하지 않는다. 실행 실패·타임아웃(15초)·출력 없음·파싱 실패는 원본 본문 그대로 — **Argon 카드만 빠지고 다른 카드는 영향받지 않는다.** 캐시는 수집 주기 단위(주기당 CLI 1회). 카드 제목 `Argon · 주간 한도`.
- **운영 env:** `ZZIK_AGY_CLI_PATH`(기본 `agy`), `ZZIK_AGY_CLI_ENABLED=0`이면 CLI를 실행하지 않는다. PM2 환경의 PATH에 `agy`(`~/.local/bin`)가 없으면 Argon만 빠지므로 배포 때 경로를 넣는다(이 브랜치는 ecosystem을 바꾸지 않았다).
