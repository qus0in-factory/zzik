# ADR 0.7: OpenCode·Ollama off-peak 배지

상태: 구현됨
날짜: 2026-11-15
기준: dev `e54580c`. 구현 정본 `0.7/offpeak-ui` `9be120d`. 조사 근거는 [0.7-offpeak-schedules.md](../research/0.7-offpeak-schedules.md), 경과 근거는 [0.7-offpeak-badge.md](../postmortem/0.7-offpeak-badge.md) (확인 2026-11-15).
같은 0.7 접두의 [0.7-usage-history-chart.md](0.7-usage-history-chart.md)와 결정 범위가 다르다. 이 문서는 그 ADR을 개정하지 않는다.

설계 초안의 Q1–Q4·Q6–Q8을 아래 결정으로 닫는다. Q5(특정 한도 창에만 적용)는 조사 문서에 창별 적용 문구가 없어 제공자 단위로 둔다.

## 1. 결론

| # | 결정 |
|---|---|
| D1 | 배지는 **섹션 제목 줄**에 둔다. 제공자당 하나. 한도 카드 안에는 넣지 않는다 |
| D2 | 비활성일 때도 배지를 그린다. 다음 off-peak **시작 시각**을 보이고, 톤은 흐리게(`muted`) 한다 |
| D3 | 배지 본문에는 시각만 둔다. **할인 문구는 툴팁(title·sr-only description)에만** 둔다 |
| D4 | 용어는 **off-peak**. 배지·툴팁의 시간대 이름은 이 영문 그대로 쓴다 |
| D5 | 구간은 **UTC 고정**. 서머타임으로 UTC 경계를 옮기지 않는다. 경계는 **시작 포함, 끝 미포함** `[start, end)` |
| D6 | **중국 공휴일은 반영하지 않는다.** OpenCode Go·Ollama 공식 문구에 공휴일 예외가 없다. DeepSeek 직접 API의 공휴일 제외를 두 제공자에 옮기지 않는다 |
| D7 | 대상은 대시보드의 **OpenCode·Ollama**뿐이다. 규칙이 없는 제공자(Claude, Codex, Antigravity, Grok)는 배지가 없다 |
| D8 | 판정은 응답 원문이 아니라 **스케줄 × 주입 시계**다. `shared/usage-scan`은 그대로 둔다 |
| D9 | 수집기 Discord 알림, Worker·DB·원격 설정은 범위 밖이다 |

## 2. 스케줄 (UTC, `[start, end)`)

요일 번호는 설계와 같다. 0=일 … 6=토. `days`는 **구간이 시작하는 UTC 요일**이다. 빈 배열은 요일이 아니므로 받지 않는다. 맞닿거나 겹치는 구간은 하나로 합친다. 시각 표기는 사용자 현지 `HH:MM`이다. `options.timeZone`(생략 시 브라우저 시간대)으로 본 현재와 전환 시각의 연·월·일이 다르면 요일을 붙인다. 배지 text와 description은 같은 시각 표기를 쓴다.

규칙은 선택 필드 `effect?: { target: string; discountPercent: number }`를 가진다. 있으면 툴팁이 이 값으로 할인 문장을 만들고, 없으면 할인 문장을 만들지 않는다. 두 제공자 모두 `{ target: 'DeepSeek', discountPercent: 50 }`이다.

`decodeOffpeakSchedule`은 `effect`가 있으면 객체인지, `target`이 trim 후 비어 있지 않은 문자열인지, `discountPercent`가 유한한 수이며 0 초과 100 이하인지 본다. 아니면 `invalid_shape`, 경로 `<provider>.effect`. `days: []`는 `invalid_window`, 경로 `<provider>.windows[<index>]`. 판정 함수는 그 잘못된 구간만 무시한다.

### OpenCode (Go 구독 사용량)

대시보드 OpenCode 카드는 ADR 0.6의 `GET https://opencode.ai/zen/go/v1/usage`이다. 배지는 그 Go 사용량에 대응하는 시간대를 쓴다.

| 요일 (UTC) | off-peak |
|---|---|
| 월–금 | `[00:00, 01:00)`, `[04:00, 06:00)`, `[10:00, 24:00)` |
| 토·일 | `[00:00, 24:00)` |

피크(배지 비활성)는 월–금 `[01:00, 04:00)`, `[06:00, 10:00)`.

맞닿은 구간을 합치면, 금요일 10:00 UTC부터 월요일 01:00 UTC까지가 하나의 off-peak다(금 10:00–24:00, 토·일 종일, 월 00:00–01:00). 토요일 한가운데의 `endsAt`은 월요일 01:00 UTC다.

할인(툴팁): 입력·출력·캐시 읽기 단가가 피크의 절반. 근거: [OpenCode Go — Usage limits](https://opencode.ai/docs/console/go/#usage-limits) (확인 2026-11-15). 한도 자체의 시간대별 증액, 요청 속도·동시성 완화는 그 문서에 없어 툴팁에 쓰지 않는다.

OpenCode Zen(크레딧 종량)은 가격표에 Peak/Off-peak가 없다. Zen 시간대는 미확인이므로 스케줄에 넣지 않는다. 근거: [OpenCode Console Models](https://opencode.ai/docs/console/models/) (확인 2026-11-15).

`source`: `https://opencode.ai/docs/console/go/#usage-limits`. `verifiedAt`: `2026-11-15`. `effect`: `{ target: 'DeepSeek', discountPercent: 50 }`.

### Ollama Cloud

| 요일 (UTC) | off-peak |
|---|---|
| 월–금 | `[00:00, 12:00)`, `[18:00, 24:00)` |
| 토·일 | `[00:00, 24:00)` |

피크는 월–금 `[12:00, 18:00)`. 공식 문장 “Off-peak pricing apply outside 12:00 and 18:00 UTC on weekdays and all day on weekends.”의 끝점 포함 여부는 페이지가 적지 않는다. 제품 경계는 D5로 통일한다.

맞닿은 구간을 합치면, 금요일 18:00 UTC부터 월요일 12:00 UTC까지가 하나의 off-peak다.

할인(툴팁): `deepseek-v4.1-flash`, `deepseek-v4-pro`의 입력·캐시 입력·출력 단가가 피크의 절반. 동시성·레이트 리밋은 플랜별 고정값만 안내되어 시간대 완화로 적지 않는다. 근거: [Ollama Cloud pricing](https://ollama.com/pricing) (확인 2026-11-15). 공휴일 문구는 [docs.ollama.com/cloud](https://docs.ollama.com/cloud)에도 없다.

`source`: `https://ollama.com/pricing`. `verifiedAt`: `2026-11-15`. `effect`: `{ target: 'DeepSeek', discountPercent: 50 }`.

### DeepSeek 직접 API (참고, 스케줄에 없음)

2026-11-15 가격 페이지는 피크를 월–금 01:00–04:00과 06:00–10:00 UTC(중국 법정공휴일 제외)로 적고, 그 밖·주말·공휴일 전일을 off-peak(피크의 절반)로 둔다. 시계 창은 OpenCode Go와 같고, 공휴일 제외만 더 있다. 그 제외는 D6으로 대시보드에 넣지 않는다. 2025-02-26의 매일 16:30–00:30 UTC(V3 50%, R1 75%)는 2025-09-05 16:00 UTC에 종료된 이전 제도다. 근거: [Models & Pricing 각주 (2)](https://api-docs.deepseek.com/quick_start/pricing/), [V3.1 가격 변경](https://api-docs.deepseek.com/news/news250821), [V4 피크/오프피크 재도입](https://api-docs.deepseek.com/news/news260813) (확인 2026-11-15). zzik 제공자 목록에 DeepSeek 직접 API는 없다.

## 3. 화면

- 위치: `SectionTitle` 왼쪽 묶음(아이콘·제목·상태등·외부 링크) 끝. 카드 보기·목록 보기·로딩·오류에서도 같은 자리에 둔다. 조회 결과와 무관해서 로딩에서 준비로 바뀔 때 제목 줄이 늘었다 줄지 않게 한다.
- 활성 본문: `off-peak · {time}까지`. 톤은 기존 사용량 정상색 테두리·글자. 색만으로 상태를 구분하지 않는다.
- 비활성 본문: `off-peak {time}부터`. 글자는 `muted-foreground`.
- 툴팁·스크린 리더: 제공자 이름, 시간대 이름 off-peak, 끝나거나 시작하는 시각. `effect`가 있으면 그 뒤에 할인 문장을 붙인다. 활성은 `{target} 단가 {discountPercent} 퍼센트 할인`. 비활성은 `off-peak 동안 {target} 단가 {discountPercent} 퍼센트 할인`.
- 문구는 `shared/messages/ko.ts`의 `offpeak.*`와 `t()`만 쓴다.

```
'offpeak.active':                         'off-peak · {time}까지'
'offpeak.upcoming':                       'off-peak {time}부터'
'offpeak.description.active':             '{provider} off-peak 시간대 · {time}에 끝남'
'offpeak.description.upcoming':           '{provider} off-peak 시간대 아님 · {time}에 시작'
'offpeak.description.discount':           '{description} · {target} 단가 {discountPercent} 퍼센트 할인'
'offpeak.description.discount.upcoming':  '{description} · off-peak 동안 {target} 단가 {discountPercent} 퍼센트 할인'
'offpeak.time.weekday':                   '{weekday} {time}'
```

## 4. 배치

설계 초안의 레이어를 채택한다. ui는 판정하지 않고 app이 만든 표시 모델을 그린다.

| 레이어 | 파일 | 내용 |
|---|---|---|
| domain | `src/domain/usage/offpeak.ts` | `OffpeakWindow` `[start, end)`, `OffpeakEffect`, `offpeakStateOf(rule, now)`, `decodeOffpeakSchedule`(effect·`days: []` 검증). 시계는 `now: Date` 주입. React·문구·경로 별칭을 쓰지 않는 순수 모듈 |
| domain | `src/domain/usage/offpeak-schedule.ts` | 2절 값만. `source`·`verifiedAt`·`effect` 포함. 값 변경은 이 파일만 |
| app | `src/app/usage/offpeak-notice.ts` | 상태 → `{ active, text, description }` |
| app | `src/app/usage/useOffpeakNotice.ts` | `useUsage`의 30초 `nowIso`를 재사용. 새 타이머 없음. 전환 반영은 최대 30초 늦다 |
| app | `UsageDeps.offpeak?` | 선택 필드. 없으면 배지 없음. 기존 테스트 조립은 그대로 둔다 |
| app | `usage-text.ts` `timeText` | UTC 등 `timeZone` 인자를 받을 수 있게 해 문구 테스트를 고정한다. 기본 동작은 유지 |
| ui | `OffpeakBadge.tsx` | `data-testid="offpeak-badge"`, `data-active`, `title`와 sr-only는 description |
| ui | `UsageSection` → `UsageDashboard` | 제목 줄에 배지. `UsageUiState` 계약은 바꾸지 않는다 |
| 조립 | `src/main.tsx` | `usageDeps.offpeak = OFFPEAK_SCHEDULE` |

`UsageDeps`에 스케줄을 주입한다. 테스트는 가짜 구간을 넣는다. 운영 스케줄 테스트는 `decode` 성공, `source`·`verifiedAt` 형식, `effect`가 `{ target: 'DeepSeek', discountPercent: 50 }`인지를 본다.

판정: UTC로 펼치고 `start <= now < end`이면 활성. 자정을 넘는 구간은 `end <= start`로 표현할 수 있으나, 2절 값은 모두 하루 안에서 끝난다(`24:00`은 그날 끝). 잘못된 구간은 그 구간만 무시하고, 유효 구간이 없거나 `now`가 Invalid Date면 null. 예외를 던지지 않는다.

## 5. 테스트

설계 초안 6절의 순서(domain → app → ui)를 따른다. 추가 단언:

- OpenCode: 월 00:59:59 UTC 활성, 월 01:00:00 UTC 비활성, 월 03:59:59 UTC 비활성, 월 04:00:00 UTC 활성, 월 06:00:00 UTC 비활성, 월 10:00:00 UTC 활성. 토 12:00 UTC 활성.
- Ollama: 월 11:59:59 UTC 활성, 월 12:00:00 UTC 비활성, 월 17:59:59 UTC 비활성, 월 18:00:00 UTC 활성. 토·일 전 구간 활성.
- 중국 공휴일로 넣은 평일 시각이 위 피크 창 안이면 비활성이다(달력 예외 없음).
- 비활성 배지가 다음 시작 시각을 흐린 톤으로 그린다. 배지 본문에 할인 문구가 없고, 툴팁·sr-only에만 있다. 비활성 툴팁은 `off-peak 동안`으로 할인이 아직이 아님을 말한다.
- 현지 연·월·일이 전환 시각과 다르면 요일을 붙인다. 같은 현지 날짜면 시각만 둔다.
- Claude 섹션에는 배지가 없다.

## 6. 범위 밖

- 응답 원문에서 off-peak 신호를 읽는 일. `shared/usage-scan`, 골든·`USAGE_HISTORY_SCAN_VERSION`, 봉투 계약은 유지한다. 근거는 2026-11-15 `scripts/usage-live-shape.sh` 실측이며, 키 집합은 [0.7-offpeak-schedules.md](../research/0.7-offpeak-schedules.md)에 있다. PostgreSQL `usage_snapshot`의 최신 ok 원문(HTTP 200, `rawOmitted` 없음)에서 OpenCode는 `usage.{rolling,weekly,monthly}.{status,percent,resetsAt}`만, Ollama는 `included.{balance_usd,allowance_usd,period}`와 `purchased.balance_usd`만 있었다. off-peak·peak·discount·multiplier 류 필드는 없었다. 픽스처 `tests/fixtures/{opencode,ollama}-usage.*.json`과 `collector/`도 같은 키 밖 할인 신호가 없다. 상류 응답에 그 필드가 생기면 스케줄보다 응답을 정본으로 재검토한다(D8).
- 수집기 Discord 알림에 off-peak를 넣는 일. 순수 모듈을 `shared/`로 올리는 일은 그때의 ADR에서 한다.
- Worker, 수집기, DB, KV, 원격 설정, 관리 화면.
- 요약 칩, 한도 카드 내부 배지, 창별 `appliesTo`.
- 정밀 전환 타이머, 중국 공휴일 달력, DST 보정, Zen 가격, DeepSeek 직접 API 배지.
- 동시성·레이트 리밋이 off-peak에 풀린다는 문구.
